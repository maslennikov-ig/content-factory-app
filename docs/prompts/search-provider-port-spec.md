# Спецификация: Tavily основным, OpenRouter запасным

**Статус:** `task spec`
**Проверено:** 2026-08-14 на коммите `1e1e6d74`
**Beads:** `content-factory-next-yqh`, решение — `content-factory-next-cty`

## Решение владельца

Основной поисковый бэкенд — **Tavily**. Запасной — **OpenRouter web plugin**, на
который переключаются автоматически, когда Tavily недоступен или исчерпан.

Решение принято 2026-08-14 по двум deep-research отчётам в `docs/research/` и
подтверждено замером на живом ключе (ниже). Отчёты расходились в том, кто
primary; выбор сделан в пользу формы ответа: Tavily отдаёт очищенный текст
страниц и ранжированную выдачу в одном вызове, а `WebResearchService` уже
написан ровно под эту форму.

## Что показал замер 2026-08-14

24 кредита, 15 вызовов, три темы, английский и русский параллельно.

| Замер                       | Английский         | Русский            |
| --------------------------- | ------------------ | ------------------ |
| `content`, глубина basic    | 1105 / 1332 / 1159 | 1060 / 1325 / 1262 |
| `content`, глубина advanced | 1946 / 1740 / 1933 | 1781 / 1808 / 1810 |
| `raw_content`, advanced     | 29k / 24k / 45k    | 48k / 27k / 19k    |
| Доля кириллицы в `content`  | 0.00               | 0.91–0.99          |

Выводы, на которые опирается спецификация:

1. **Задокументированной обрезки неанглийского контента нет.** Риск из
   `tavily-python` issue #29 на русском не воспроизвёлся: длины идут вровень, на
   двух темах из трёх русский длиннее. Это снимает главную неизвестность
   решения.
2. **`include_raw_content` даёт на порядок больше материала** — 15–48 тысяч
   знаков против 1–2 тысяч, и приходит для всех пяти результатов. Сейчас он
   выключен.
3. **Выдача действительно русскоязычная** — доля кириллицы 0.91–0.99.
4. **`country: russia` не вредит и слегка помогает**, но безусловной пользы не
   даёт.

Оговорка: глубина `advanced` и `include_raw_content` включались вместе, их
вклады не разделены.

## Работа

### 1. Включить то, ради чего Tavily выбран

- `include_raw_content: true`.
- Глубина по умолчанию `advanced` вместо `basic`. Сохранённый выбор `basic`
  должен соблюдаться и не перезаписываться при сохранении другой настройки.
  Advanced стоит 2 кредита вместо 1; замер показывает, что это окупается
  материалом как дефолт.
- `country` подставляется из `subjectLanguage`/`scope` классификатора, а не
  прибивается к России: продукт ведёт английский и русский как равные языки.
- `time_range` и `topic: news` для тех запросов, где промпт требует свежести.

### 2. Ограничить сырой текст перед промптами

Обязательное следствие замера. Пять источников по 15–48 тысяч знаков на два
запроса — это до четверти миллиона знаков в четыре промпта. Нужен явный
потолок на источник и общий потолок на совокупный текст фактов, оба записанные
константами рядом с `WEB_SEARCH_TIMEOUT_MS` и объяснённые в комментарии. Summary,
title и URL источников в этот потолок не входят. Обрезка предпочитает границу
абзаца; если её нет внутри потолка, источник режется по символу, а не исчезает.

### 3. Запасной OpenRouter

- `SearchProvider` расширяется до `'tavily' | 'openrouter'`; появляется ветка
  сборки клиента OpenRouter web plugin с `engine: parallel`, `mode: advanced`.
  Форму запроса и ответа брать из действующей документации OpenRouter на день
  сборки, а не из памяти.
- Переключение **автоматическое и только по отказу**: 429, исчерпанная квота
  (402/403), 5xx, таймаут, пустая выдача. Недовольство качеством — не отказ, оно
  меняется настройкой, а не кодом.
- **Отсутствие ключа отказом не считается.** Организация, у которой поиск
  выключен или ключ не задан, остаётся без поиска. Иначе запасной путь начнёт
  молча тратить бюджет модели там, где владелец поиск не включал.
- Запасной путь доступен только организациям, у которых `provider` модели —
  `openrouter`: он платится тем же ключом. Для организации на OpenAI запасного
  пути нет, и это состояние надо показывать в настройках, а не скрывать.
- Общий бюджет времени на исследование не должен удваиваться: у основного пути
  свой дедлайн, у запасного свой, сумма остаётся ограниченной.
- Результат обязан нести, кто именно ответил. Ответ запасного пути структурно
  беднее — цитаты вместо текста страницы, плюс оплаченные токены модели, — и
  молчаливая деградация недопустима: провайдер пишется в лог и возвращается
  структурным полем. Отдельная UI-метка не входит в эту задачу.

## Чего делать нельзя

- Реальные внешние вызовы в тестах и в сборке.
- Запасной ключ из окружения, raw SQL, правки контрактов Temporal и провайдеров
  соцсетей.
- Отдавать дедлайн обратно инструменту: причина записана в комментарии рядом.
- Трогать `apps/frontend/src/components/launches/**` и `new-launch/**` —
  параллельный поток владеет ими.

- `pnpm run build` — код 0; `pnpm test` зелёный, включая новые наборы;
  `node scripts/branding/brand-scan.cjs` — 0 unexplained.
- Организация на Tavily получает выдачу с сырым текстом, ограниченным потолком.
- Отказ Tavily переводит запрос на OpenRouter только у организаций на
  OpenRouter, и это видно в логе; отсутствие ключа переключения не вызывает.
- Тесты покрывают: изоляцию двух организаций, выключенный поиск, отсутствие

  границу обрезки сырого текста.
