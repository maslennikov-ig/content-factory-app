## 3. Решения (что меняем)

### 3.1. «Берём» по ключу строки (`xmfb.1`, P1)

- Дверь `PATCH /pieces/:id/facts` принимает `{ factKey, selected }`; для старых строк без
  ключа — `statement` (версия DTO, старый вход читается). Поиск строки:
  `fact.factKey === key || fact.statement === key`.
- Строки нет → своя ошибка `PIECE_FACT_NOT_FOUND` (409), не `PIECE_NOT_FOUND`.
- Экран: `piece.container.tsx` шлёт `factKey`; ошибка показывается рядом со строкой
  («Выбор не сохранён»), галочка возвращается.
- Тест: строка с `factKey` из `acceptCoreResearch` переключается туда и обратно; `ungrounded`
  и суть не трогаются.

### 3.2. «Проверить факты» не падает целиком (`xmfb.2`, P1)

- Web-режим — **только фактические правки**: не отправлять `catalogFindings` и правила
  стиля, промпт говорит «исправляй только то, что противоречит источникам».
- Валидация **по правке, а не по отзыву**: правка текста без `sourceUrls` → заметка
  (`replacement = excerpt`); адрес не из `webReviewSources` → убрать адрес (нет адресов →
  заметка); `excerpt` не найден или пересекается → правку выбросить; больше 40 → обрезать
  заметки. `REVIEW_INVALID` остаётся только для непарсимого ответа.
- Один повтор при непарсимом ответе с объяснением ошибки модели (идея `75xn.35`).
- Причина отказа — в журнал (`Logger.warn` с кодом проверки, без текста пользователя).
- Сбой ревью **не списывает** квоту: статус `failed` не считается в
  `includedUsageFilter` для ревью (поиск, который реально прошёл, считается).
- Тест на записанном ответе с стилистической правкой без источника и с адресом со
  слэшем: отзыв возвращается, правка стала заметкой.

### 3.3. Чужой пост узнаётся, и позиция спрашивается (`xmfb.3`, P1)

- Вид материала определяет **модель** на шаге `extract` (поле `materialKind:
  thought | foreign_post`, новая версия схемы extract), эвристика `detectInputKind`
  остаётся запасной (и для ссылок). Признак чужого поста: текст написан как готовая
  публикация о событии/мнении, а не заметка к себе; «Мне кажется» внутри поста — мнение
  его автора, а не человека.
- При `foreign_post` позиция человека **неизвестна**: `origins.position` не `input`.
  Кодовое правило на входе: если `foreign_post` без позиции человека или
  `origins.position === 'model'` — добавить вопрос `position` через
  `core-questions.ts` (`openQuestionsFor` / `textOf('position')`), варианты от первого
  лица; вместе с вопросом модели — не больше двух.
- Мысль с тезисом и позицией (Исландия) — вопросов нет, это верно (ответ владельцу на A1).
- Ручного переключателя «это чужой пост» **не добавляем** (правило «решаем за человека»).
- Тест: текст из страницы седьмого захода (WB/Ozon) на записанном ответе extract даёт
  `foreign_post` и вопрос о позиции.

### 3.4. Язык поиска и журнал запросов (`xmfb.4`, P1)

- Классификатор: `local` — только когда тема про законы, рынок, компании или учреждения
  **страны читателя** (язык вывода/области) или когда искать имеет смысл только внутри
  одной страны; опыт другой страны, обсуждаемый как идея (Исландия и четырёхдневка), —
  `global`: запрос на языке темы + английский, без `country`.
- Записывать в журнал операции (`Logger.log`, как «answered via») классификацию
  (`scope`, `subjectLanguage`, `country`) и число запросов; текст запроса — только тема
  одной строкой, без ключей и адресов области.
- Тест на записанной классификации: Исландия → два запроса без страны; WB/Ozon → один
  русский с `country: russia`.

### 3.5. «Дополнить ресерчем»: куда копать и глубина (`xmfb.5`, P2)

- `PieceResearchDto`: `level` (`quick|standard|deep`) и `direction?` (`MaxLength 300`);

### 3.7. Сортировка «Заготовок» (`xmfb.7`, P2)

- Готового элемента нет (`UpDown` из analytics — наследие Postiz: hex, div, без
  клавиатуры). Единый элемент: **`Th` получает необязательный `sort`**
  (`{ direction: 'asc'|'desc'|null, onToggle }`) — настоящая `<button>`, `aria-sort`,
  стрелка токенами. Запись в `docs/design/component-inventory.md` тем же коммитом.
- На карточках (<720px) тот же порядок — `Select standalone` «Сортировка» в `FiltersRow`
  («Сначала новые», «Сначала старые», «Название А–Я», «Название Я–А», «Формат»). Одно
  состояние на оба вида.
- Поля: код (= дата создания), название, формат, дата; ↑/↓. Умолчание — «сначала
  новые». Сортировка на клиенте, API не меняется; порядок хранится в адресе
  (`?sort=date:desc`), чтобы ссылка открывалась так же.

### 3.8. Ключи поиска по движку (`xmfb.8`, P2)

- Перед кодом — `technical-premortem` (ключи, биллинг, квота).
- Разрешение ключа для движка: **свой ключ движка области → системный ключ движка**.
  Переключатель «Ключи системы / Свой ключ» продолжает управлять **генерацией**; поиск от
  него отвязан.
- Карточка «Веб-исследование»: по полю на движок, подпись поля «На ключе системы» или
  «Свой ключ», кнопка «Вернуть на ключ системы» (удаляет свой ключ этого движка,
  `clearSearchKey`). Абзацы `systemKeysOnly` и `includedOwnKey` убрать; одна строка
  `Hint` у заголовка объясняет правило.
- Источник ключа (`own | system`) передаётся вместе с ключом до учёта расхода: поиск на
  своём ключе **не списывает** включённую квоту; на системном — как сейчас.
- Маршрутизация задач (`ai.search-tasks.ts`) видит объединённую карту ключей; откат на
  другой движок — как сейчас, никогда не OpenRouter. Страж
  `tests/ai.search-routing.guard.test.cjs` обновить. Схема базы не меняется.
