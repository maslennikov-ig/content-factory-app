# Решение по упрощению анализа стиля, 08.10.2026

По задаче `content-factory-next-0qgn.17` сохраняется текущий анализ стиля.
Результат ограниченного сравнения имеющихся доказательств — **INCONCLUSIVE**:
качество альтернативы не подтверждено. Это решение предусмотрено действующими
критериями задачи. Сокращение выборки, групповой анализ, новый режим интерфейса
и изменение исторических профилей в этом этапе не внедряются.

## Что сравнивалось

Проверены текущий исходный путь и сохранённые результаты настоящих вызовов
модели. Кандидат — анализ тех же выбранных текстов группами, с сохранением
привязки каждого наблюдения к своему тексту. Новый модельный эксперимент
не выполнялся: в проверенных материалах нет результатов этого кандидата
и парных публикаций, которые позволили бы принять замену.

Историческое принятие датировано 02.10.2026 и относится к версии
`cb456e7b0479a8bf688391d444aa3ba354eac1f0`. Это ограниченное свидетельство
работоспособности прежнего пути, а не свежая семантическая приёмка текущей
версии или доказательство качества на настоящих авторских корпусах.
Восемь синтетических текстов также не проверяют работу выборки 28 текстов.
Состояние калибровки в исходном принятии — `TOO_FEW_OWN`.

## Подтверждённое устройство текущего анализа

Основание проверки исходников — коммит
`016b0818424eb2d129651d04d3a6916d09f0ff50`. Файлы приложения не изменены.

- `sampleLimitFor`: 28 образцов при размере корпуса от 100, 20 — от 40,
  иначе до 12. `selectSamples` распределяет выбранные позиции по всему
  переданному порядку; это не гарантия тематической стратификации.
- `runAssistV2` делает отдельный map-вызов для каждого выбранного текста
  и один reduce по полученным наблюдениям. Map допускает до шести наблюдений
  на текст. Числа по привычкам и раскладке считаются по корпусу отдельно.
- Цитата проверяется по тексту образца, ссылки имеют вид
  `sampleCode#position`. Сводка просит сохранять повторяющиеся выразительные
  привычки, только когда их поддерживают разные образцы.
- Два schema-attempt допускаются для отдельного вызова; сервис может
  повторить весь анализ при недостаточно обоснованном результате.
  29 — число логических шагов успешного первого прохода, не верхняя граница
  обращений провайдеру и не число вызовов на каждую публикацию.

Объединение образцов без изменения схемы, допускающей только один `sampleCode`
и шесть наблюдений, сократило бы ёмкость свидетельств. Для корректного
эксперимента каждый выбранный образец должен иметь собственные наблюдения,
тот же предел на образец и собственную проверку цитат. Для 28 образцов это
до 168 наблюдений до существующей дедупликации. Само объединение запросов
не доказывает сохранения внимания модели ко всем текстам.

## Проверка потерь полей профиля

`assist.contract.ts` ограничивает описание поля 600 символами, портрет —
200–1200. После проверки оснований текущий V2-путь объединяет дубли полей
и применяет `proposal-quotation-guard.ts`.

Этот guard сохраняет точный законченный префикс либо опускает поле в
предусмотренных случаях незавершённой цитаты или граничного незавершённого
текста. Проверка обычной прозы относится к `TONE` и `TOPICS` около 599–600
символов. Она может убрать последний смысловой фрагмент намеренно написанного
без завершающей пунктуации текста; исходник прямо называет эту границу.
Обоснованность цитат и такая формальная проверка завершения — разные условия.

Сохранённый offline replay подтверждает изменение длины описания и точность
оставшегося префикса на конкретных модельных ответах. Он не сравнивает
публикации до/после и не доказывает улучшение или ухудшение стиля. Свежая
фактическая потеря авторской привычки из-за фильтра в этом этапе не установлена.
Исторические профили фильтр не переписывает. Менять его вместе с непроверенной
группировкой означало бы одновременно менять два условия сравнения;
фильтры сохраняются.

## Точная недостающая проверка

Для принятия группировки нужны два анализа **одного и того же** разрешённого
корпуса с одинаковыми выбранными образцами, измерениями, языком, настройками
модели и подлинными примерами, затем публикации по одинаковым заданиям
через фактический путь потребления профиля. Должны сохраняться сырые ответы,
проверенные наблюдения, профиль до и после фильтров и конечные публикации.

Ограниченная содержательная проверка сравнивает узнаваемость голоса,
естественность связной прозы, сохранение характерных привычек и отсутствие
придуманного юмора, фактов или чужой позиции. Человек не должен исправлять
поля слабого профиля ради прохождения сравнения. Структурные тесты,
число заполненных полей, токены и количество вызовов не заменяют чтение
публикаций. Автоматический дополнительный модельный проверяющий не нужен.

В этом этапе такого сопоставления нет. Нельзя утверждать ни равенство,
ни ухудшение альтернативы. Без доказательств принимается предусмотренное
критериями решение **RETAIN_CURRENT**, а не новое продуктовое поведение.
Будущий эксперимент не является обязательным продолжением этого решения.

Минимальная постановка, если владелец выберет отдельный эксперимент:

1. Один разрешённый корпус; `selectSamples` выбирает образцы один раз.
   Полные тексты остаются в приватном пакете основного агента. Измерения,
   идентификаторы, порядок и хеши входов одинаковы для обоих вариантов.
2. Baseline — неизменённый `runAssistV2`; кандидат — группы максимум по
   четыре выбранных текста. Каждый результат группы содержит отдельный
   `sampleCode` и до шести наблюдений **на каждый текст**. Проверка цитат,
   ссылки, reduce, объединение полей и фильтры остаются одинаковыми.
3. При восьми выбранных образцах это 9 логических шагов baseline и
   3 кандидата; при 28 — 29 и 8. Это бюджет первого прохода анализа;
   допустимые schema/provider-повторы назначаются отдельно до запуска.
   Восьмитекстовый пилот может отсечь плохой кандидат, но не принять его
   в качестве default для корпуса от 100 текстов.
4. Два одинаковых задания обоим профилям: одно с характерным для корпуса
   отношением к читателю, второе на другую тему без оснований для той же
   шутки. Получаются четыре конечные публикации. Их порядок при чтении
   скрывает название варианта. Факты, позиция и длина задаются одинаково.
   Профили и тексты до чтения вручную не исправляются.
5. До отправки основной агент фиксирует конкретную модель, лимиты контекста
   и вывода, совокупный токенный/денежный предел и число возможных вызовов
   фактического пути публикации. Из имеющихся receipts эти параметры
   будущего запуска определить нельзя; существующий счёт не является
   разрешением или оценкой его стоимости. При выходе за предел прогон
   прекращается и получает `INCONCLUSIVE`, без скрытого продолжения.
6. Утрата характерной привычки, придуманная самоирония, сглаженная одинаковая
   манера на разных темах или потребность ручного восстановления профиля
   отклоняют кандидат. Четыре удачных текста дают ограниченный сигнал,
   а не статистическую эквивалентность. Любая неоднозначность сохраняет
   `RETAIN_CURRENT`; уменьшение числа вызовов не компенсирует её.
