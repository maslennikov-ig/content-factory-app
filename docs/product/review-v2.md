# Проверка и перегенерация текста — v2

`adaptation-review/v2` — преемник v1. Старые промпт и контракт сохраняются;
контроллер использует v2. Схема БД не меняется.

- `POST /content-intelligence/pieces/:id/rewrite {instruction}` и
  `POST /content-intelligence/pieces/:id/adaptations/:aid/rewrite {instruction}`:
  обязательная непустая инструкция, один вызов роли review, без повторов модели.
- `POST /content-intelligence/pieces/:id/adaptations/:aid/review {mode}`:
  slop/facts/both; web требует `confirmWebSpend: true`, отдельно запускает поиск,
  затем один вызов проверки. Поиск ограничен первыми 5000 знаками.
- Приём через `/:id/rewrite/accept` либо `/:id/adaptations/:aid/review/accept`:
  `{token, selectedIds, variant?}`. Клиент не присылает новый текст.

Ответ содержит `changes[{id,excerpt,replacement,ruleId?,why,basket,target?,variants?,sourceUrls?}]`,
`verdict`, `summary`, исходный и предлагаемый текст, счёт каталога до/после и token.
Корзина silent предназначена для однозначных опечаток, show — для редакционных
предложений, ask — для изменения смысла или нехватки факта. Все изменения ждут
принятия; silent выбрана по умолчанию, её тоже можно снять. Ask не меняет текст
даже при ошибочном replacement от модели. Вопросы появляются в «Опорах текста». Ответ автора сохраняется через прежнюю
дверь /answer с расширением reviewAnswer {token, adaptationId?, answers:[{questionId,text}]}.
Подписанный ask ID, организация и текущие снимки проверяются до записи.
Ответ и вопрос сохраняются в core.brief.reviewAnswers, ответ дословно добавляется
как собственная опора origin:person/kind:own/verified:false. Найденные факты
не меняются. Запись использует metadata CAS, модели не вызывает; после неё
экран перечитывает опоры, прежнее предложение проверки сбрасывается. Частичный
ответ возвращает оставшиеся вопросы с новой подписью и обновлённым снимком:
следующий ответ сохраняется, старый токен больше не действует.

Предложение подписано HMAC с серверным JWT_SECRET, областью организации,
идентификаторами заготовки/адаптации и сроком 30 минут. Приём применяет только
известные выбранные ID к подписанному исходнику. Неоднозначные, пересекающиеся
правки, повторные ID и пустой итог отклоняются. Для адаптации сохраняется
транзакционный CAS по телу/версии поста и адаптации. Для сути CAS сравнивает
body, title и весь brief: параллельная правка фактов, ответов или заголовка не
теряется. Метаданные и признак ручного заголовка сохраняются.

Находки бесплатного каталога передаются модели с ruleId, excerpt и смещениями.
Модель исправляет каждую или объясняет, почему оставляет. Семантические критерии
из `review-semantic.v2.ts` требуют контекста: его нехватка означает вопрос,
а не выдуманный факт. Найденная ссылка и выбранная опора не означают верификацию.
Web-исправление требует ссылки на реально полученный источник; это не проверка
всех утверждений текста.

Два чипа заполняют инструкцию и не вызывают модель. Для заголовка модель даёт три
различных варианта: промпт запрещает неподтверждённые обещания и события, сервер
также отклоняет новые числа. У адаптации заголовок хранится отдельно в ContentDerivation.title. Только для
старого null-заголовка исходником служит первая непустая строка. При принятии
заголовок и текст записываются атомарно с CAS, включающим прежний title. Первая
строка поста/тела синхронизируется только когда она точно совпадала со старым
заголовком; самостоятельный первый абзац не меняется. Выбор варианта принимает его
вместе с отмеченными правками. Пустая суть до ответов не доступна для перегенерации.

Экран показывает исходный текст один раз, локальные удаления/вставки и причины
через title/Hint; ниже — тот же список с флажками. Источники раскрываются общим
Disclosure. Когда правок нет, кнопок принятия/отказа нет. «Опубликовать» открывает
существующий редактор поста; внешняя отправка этим действием не выполняется.
«Усилить ресерчем» будет подключено с отдельной операцией эпика ресерча: сейчас
кнопки без рабочего действия нет.
