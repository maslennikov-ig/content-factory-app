# Волна второго захода 08.09.2026: путь без тупиков, страница заготовки v2, навигация-конвейер

Дата: 08.09.2026. Боевой выпуск на момент прогона: `5f657ccf294e`. Эпик Beads:
`content-factory-next-tu3k.14` (25 задач, потоки S0–S8). Заметки владельца целиком и
скриншоты: `.codex/stages/content-factory-next-fn33/evidence/walk-2026-09-08/`.
Макеты: `docs/design/desert-lab/pipeline/`. План исполнения для оркестратора:
`docs/prompts/astra-second-walk-wave-2026-09-08.md`.

Это спецификация правок по второму живому прогону владельца. Первый заход 07.09 закрыл
«заготовка не создаётся». Второй показал: продукт работает, но не складывается в путь.
Ниже — что решено, почему, и что считается сделанным.

## 1. Решения владельца (08.09, дословно из чата и страницы теста)

1. **Вход без «Куда».** «Заготовка-то у нас нейтральная. Зачем нам выбирать, куда мы её
   пишем? Это потом уже во время адаптации». Короткий путь «Сделать и написать для
   канала» владелец назвал ошибочным. Решение: снять блок и короткий путь; вход — одно
   поле, канал и его карточка выбираются на странице заготовки.
2. **«Что уже написали» снять.** «Да, сними. Если оттуда что-то можно полезного перенести в
   основной вид, перенеси. Если полезного ничего нет, то не переноси». Проверено: вид
   дублирует клетки площадок и поиск по постам. Переносится только счётчик: клетка площадки
   показывает «2 поста», когда постов больше одного. Индекс и блок «Свои тексты по теме»
   остаются.
3. **Платная проверка черновика — с выбором.** «Если меня всё устраивает, я не хочу проверять
   факты. А хочу только проверить на то, что здесь нету ИИ-слопа… либо одно, либо другое,
   либо всё сразу. Потому что это ведь больше токенов будет тратиться у человека».
   Решение: одна кнопка «Проверить ▾» раскрывает меню из трёх режимов, у каждого подпись
   стоимости.
4. **Навигация-конвейер.** «Должна быть какая-то последовательность: сборка контента,
   заготовки, каналы, выбор публикаций в календаре… Нарисуй мне несколько вариантов, а я
   выберу лучший». Решение: три варианта на холсте, выбранный внедряется в эту же волну.
   **Выбор владельца 08.09: вариант A «Конвейер в меню»** (`NavConveyor.dc.html`): меню в
   порядке пути с номерами шагов — С чего начать → Аватар → Каналы → Заготовки → Календарь
   → Аналитика; «Контент» распадается на пункты; «Каналы» ведут на список каналов.
5. **Проверка на стенде до выпуска.** «Давай мы с тобой сделаем редизайн, и ты меня локально
   запустишь, я посмотрю… прежде чем тратить столько времени на деплой». Решение: страница
   заготовки и таблица показываются владельцу на локальном стенде до выпуска.

Решения 07.09 остаются в силе: адаптация не ищет в интернете; галочек и кнопки «Проверил»
нет; «С чего начать» — пункт меню до прохождения шести шагов; посты в Telegram выходят от
имени канала.

## 2. Что нашли и почему так (коротко; полные причины в задачах Beads)

| Симптом у владельца | Причина |
|---|---|
| Разбор аватара «висит на 4%» и падает | Экран мастера размонтирует себя, когда арифметика записана в базу, и рвёт поток (nginx 499 через ~60 с); `compression()` держит строки NDJSON в буфере; heartbeat нет |
| «Опубликовать сейчас»: «подтверждения устарели» | Серверные ворота контекста живы: требование отметки «проверил» и 15-минутный срок снимка; `POST /posts` → 409 |
| «Много эмодзи», а эмодзи нет | Значение `free` в промпт превращается в пустую строку; правила Telegram уходят любой площадке; ответ о форме не влияет |
| Вопросы адаптации непонятны | Варианты ответов есть в коде, но не доезжают до экрана; вопрос о призыве задаётся, хотя призыв есть в карточке |
| Страница заготовки «прилеплена», «В архив в воздухе», «формат auto» | Единственная страница раздела без обёртки с отступами; значения брифа печатаются сырыми; одно и то же сказано дважды; адаптация показана дважды |
| Строка таблицы не открывает заготовку, «ещё нет» уводит | У строки нет клика; чип «ещё нет» молча запускает платную адаптацию |
| Слово не подсвечено при рабочем поиске | Три разных правила поиска: сервер по словам, клиент по фразе, подсветка по точной форме |
| Нет лоудера на входе; «что изменилось после ответа» | Индикатор без движения, старая суть не хранится, событие несёт только новую |
| Ссылка вместе с чужим постом | Ссылка молча теряется, берётся только текст |
| «Расход» не находится | Таблицы называются «Операции ИИ …» |

## 3. Что делаем (потоки)

- **S0 Макеты (сделано Claude 08.09).** Холст `docs/design/desert-lab/pipeline/`: три
  варианта навигации, страница заготовки v2, таблица v2, вопросы с вариантами, меню
  проверки, вход одним полем. Владелец выбрал вариант навигации A; S6 не ждёт.
- **S1 Публикация и промпт.** Ворота контекста не блокируют публикацию при политике, отличной
  от `EVIDENCE_REQUIRED`; меню публикации с `flex`; каждое значение карточки канала даёт
  явную строку в промпте; телеграм-строки только Telegram; антикопия на пути заготовки.
- **S2 Аватар из текстов.** Мастер не размонтируется во время разбора; NDJSON мимо
  сжатия, `X-Accel-Buffering: no`, heartbeat каждые 10 с; живой прогресс; образцы — новейшие,
  лимит 300, подпись «взяли N последних из M».
- **S3 Вход и вопросы.** Вход без «Куда» и без короткого пути; один живой индикатор; поле
  «О чём будем писать»; ссылка + текст берутся оба; чужой пост не считается «своим»;
  после ответа видно, что изменилось; вопросы адаптации с вариантами, призыв из карточки.
- **S4 Страница заготовки v2 и таблица.** По макетам; строка кликабельна; «ещё нет» без
  платного вызова; фильтр «архив»; один поиск со стеммами; вид «Что уже написали» снят.
- **S5 Копи.** «Расход ИИ по участникам / по ролям».
- **S6 Навигация-конвейер.** По варианту A: меню «Путь» с номерами шагов, «Контент» распадается
  на пункты «Аватар», «Каналы», «Заготовки»; вкладки «Откуда идеи» и «Откуда факты» уходят под
  «Заготовки»; пункт «Каналы» — список каналов; из календаря — в заготовку.
- **S7 «Проверить ▾».** Дверь `POST /content-intelligence/pieces/:id/adaptations/:adaptationId/review`
  с `mode: slop | facts | both`, один вызов модели, результат с пометками, «Принять» / «Оставить».
- **S8 Замер живости по базе.** Скрипт без модели: доля слов человека, дошедших до адаптации
  дословно. Ответ на G1–G3 без прогона владельцем.

## 4. Поведение, которое считается сделанным

- *Дано* заготовка из мысли и карточка Telegram с «много эмодзи»; *когда* владелец жмёт
  «Адаптировать · Telegram» и отвечает на вопросы с вариантами; *тогда* текст содержит эмодзи,
  призыв из карточки, форму из ответа, в объекте адаптации виден черновик, строка качества и
  кнопка «Проверить ▾» с тремя режимами.
- *Дано* черновик, написанный дольше 15 минут назад; *когда* «Опубликовать сейчас» из меню;
  *тогда* пост уходит в канал без «подтверждения устарели».
- *Дано* выгрузка Telegram на 150+ сообщений; *когда* запущен разбор; *тогда* полоса движется с
  первой секунды, экран не переключается, разбор доходит до предложения.
- *Дано* таблица заготовок; *когда* клик по строке; *тогда* открывается страница заготовки;
  шеврон раскрывает строку на месте; чип «ещё нет» не тратит вызов модели; фильтр показывает
  архив; найденное слово подсвечено в заголовке или сути.
- *Дано* ввод «ссылка + текст чужого поста»; *когда* «Сделать заготовку»; *тогда* в «Что модель
  поняла» стоит «чужой пост + ссылка», страница по ссылке прочитана.
- *Дано* ответ на «Уточнение»; *тогда* изменённые предложения сути подсвечены; при одном
  «Реши сама» — подпись «суть не менялась».
- *Дано* вариант навигации A; *тогда* меню и вкладки переставлены, пункт «Каналы»
  ведёт на список каналов, пост в календаре ведёт на заготовку.

## 5. Не делаем в этой волне

Публикация в Telegram от своего имени (MTProto) — решение владельца m2eg.25 остаётся.
Судья черновиков `DRAFT_PICK_SHIPPED` не включается. Схема базы не меняется (проверки
не сохраняются, индекс поиска в памяти). Замер живости G1–G3 владелец не повторяет.

## Уточнение после просмотра стенда 08.09

Владелец просмотрел страницу cnt-01 и таблицу: «Как пишем» должна выглядеть кнопкой; обратный переход — «Все заготовки»; сверху нужна таблица площадок с иконками, состоянием адаптаций и явными действиями; опоры текста свёрнуты по умолчанию; null и auto заменяются понятными значениями.

Автоматическая проверка утверждений поиском при создании заготовки отключается. Поиск для обогащения содержания при нехватке информации сохраняется. В меню проверки добавляется отдельный пункт «Проверить поиском» с предупреждением о расходах. Он не заменяет сверку с сутью, запускается только по явному подтверждению, показывает источники и не меняет черновик до «Принять». Правило одного вызова модели сохраняется для исходных трёх режимов; отдельная проверка поиском дополнительно расходует поиск. Платных вызовов в тестах нет.
