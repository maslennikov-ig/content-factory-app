## 4. Вопросы (решение 8)

- **На входе**: вызов, который читает материал (`intake extract`), возвращает
  поле `questions[]` (≤3) — только там, где материала не хватает для тезиса,
  позиции или факта; каждый вопрос **сформулирован по тексту человека**, с 2–3
  вариантами и «Реши сама». Суть пишется **после** ответов одним вызовом
  `draft`. Нет пробелов — нет вопросов, суть пишется сразу. Ответы дословно, как
  сейчас. Мёртвый второй круг (`roundOf`) убирается.
- **При адаптации**: шага вопросов нет. Вызов адаптации может вернуть один
  вопрос **только** если поле карточки канала стоит «выбирает модель» и модель
  не может выбрать без человека (`unavoidable: true` с причиной). Иначе пишет.
  Заготовленные вопросы «форма / призыв / зацепка» снимаются: форма и призыв
  берутся из карточки или решаются моделью.
- Экран говорит, откуда вопрос: «Модель спросила по вашему тексту» /
  «Не хватает для канала «…»».

## 5. Проверка, штампы, перегенерация

### 5.1. Результат проверки читаемо (решение 5)

Контракт ответа проверки меняется с «весь текст + notes[]» на список правок:

```
changes: [{ id, excerpt, replacement, ruleId?, why, basket: 'silent'|'show'|'ask',
            variants?: [string, string] }]
verdict: 'clean'|'review'|'rewrite', summary: string
```

Три корзины из донора (`review-pipeline.md`): **правим молча** (опечатки,
арифметика, битая ссылка — один правильный вариант), **правим и показываем**
(стилистика, штампы — «было → стало», можно откатить каждую), **спрашиваем**
(всё, что меняет смысл или требует факта, которого нет — вопрос автору, не
удаление). Экран: один текст через `sentenceChanges` (`core-answer-diff.tsx`),
удалённое и добавленное как в diff кода, **объяснение при наведении** на
изменённое предложение (`title` + всплывающая подсказка `Hint`) и тот же список
под текстом; «спрашиваем» — отдельным блоком вопросов с полем ответа.
«Правки не понадобились» — одно уведомление без кнопок. «Источники поиска» —
свёрнуто (`Disclosure`). Принять всё / принять по одной (галочки у строк
списка) / оставить как было.

### 5.2. Находки каталога → в промпт (решение 6)

Образец уже есть: `core-write.ts` `REPAIR` для антикопии (цитаты находок →
один повторный заход внутри той же операции). То же для штампов: `slopCheck`
даёт `ruleId`, `excerpt`, `start/end`; «Убрать штампы» и любая перегенерация
получают список **этих** находок с просьбой исправить каждую или объяснить,
почему нет; после правки каталог считается снова, экран показывает «было N →
стало M». Промпт получает строки «не гонись за баллом», «если исчезли личные
примеры и позиция — ты обезличил», «правка требует факта, которого нет — задай
вопрос». Ответ на вопрос владельца «почему модель сама ничего не нашла»:
проверка получала 40 фраз по кругу из 89 и не знала о находках каталога из
30 правил, из которых 7 — метрики, а не фразы.

### 5.3. «Перегенерировать» (решение 7, уточнено 10.09 вечером)

Владелец: «должна быть кнопка «Перегенерация», а там появляется вопрос: «А что вы
хотите перегенерировать?» И ты текстом пишешь, и модель это получает как правило
для перегенерации. Там человек может указать только заголовок, к примеру, или
что-то поменять в тексте, чего не хватает». Одна кнопка на сути и на адаптации →
поле «Что перегенерировать?» свободным текстом (обязательное), два чипа-подсказки
«Только заголовок» и «Весь текст» лишь подставляют текст в поле. Один вызов
модели: инструкция человека, текущий текст, находки каталога штампов (§5.2),
правила «не добавляй фактов сверх опор, не обезличивай, меняй только то, о чём
просят». Ответ в контракте §5.1, показ через diff с объяснением при наведении,
«Принять» / «Оставить». Просят заголовок — модель даёт 3 варианта с гейтом
честности из донора (`headline-hooks.md`), выбор одним кликом. Заголовок
заготовки после ответа на вопросы пересчитывается, если был запасным (§5.5).

### 5.4. Блок адаптации (решение 4)

Первичная кнопка «Опубликовать» (открывает окно поста, как со страницы
заготовки), рядом «Ещё ▾»: «Переписать ▾», «Убрать штампы», «Сверить с сутью»,
«Проверить факты поиском», «Усилить ресерчем» (§6). У каждого платного пункта —
подпись стоимости. `loading` на кнопках, `Progress` на месте ожидания.

### 5.5. «:null» — причина и починка

Строка `":null,"` пришла в поле `goal` ответом модели: схема просит «return
null», материал показан в форме «подпись: значение» (`borrowedSummary` через
`oneLine`), `topic`/`angle` обязательные строки (модель пишет «null» строкой),
мягкий разбор LangChain принимает любую строку, `textOrNull` пропускает любую
непустую. Починка: (1) `textOrNull` и разбор `facts` отбрасывают заглушки
`null|none|undefined|n/a|нет` с любыми `:",` вокруг; (2) `topic`/`angle`
`nullable`; (3) запасной заголовок — первые слова сути, не `goal`; (4) заголовок
пересчитывается после ответов; (5) дверь `PATCH /pieces/:id {title}` и правка
кликом; (6) наблюдаемость: при отбросе заглушки — `logger.warn` с полем и
операцией, и на 14 дней включить журнал сырых ответов входа в `AiUsageRecord`
нельзя (нет колонки) — вместо этого писать в лог приложения усечённый ответ при
любом отброшенном значении.

  языках предмета и `en`. Строка Wikipedia читается второй раз через
  `/api/rest_v1/page/summary/{key}` и даёт выдержку, которую можно цитировать
  (до 2000 знаков); Wikidata статьи не имеет, поэтому становится источником без
  факта. Полоса живёт в том же потолке источников и том же бюджете символов,
  что и провайдер, проходит ту же политику выпуска трафика (`kind: 'fetch'`,
  `wikipedia` и `wikidata` в списке разрешённых) и ограничена собственным
  сроком в 8 секунд. Её отказ пишется в журнал и никогда не отменяет уже
  полученный ответ поисковика. Без явного уровня — обычная генерация,
  автопостинг, копайлот — полоса не открывается совсем.
