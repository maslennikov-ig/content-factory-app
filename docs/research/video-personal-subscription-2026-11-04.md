## Runnable product flow

1. An authorized workspace admin enables the existing subscription policy. `GET /media/video-access` reports `connectReady` independently of `generationReady`; legacy `enabled` retains generation semantics.
2. The existing provider `/start` endpoint uses the saved draft/piece/job return path, first-party dynamic registration and OAuth S256/state/resource/issuer/session checks. At owner account connection, a missing reviewed wallet profile saves encrypted, actor/workspace-bound authorization as `discovery_required`. A reserved `unverified:` namespace in the legacy digest column is never wallet/billing evidence. Expired provisional authorization requires reconnect; it cannot silently refresh into a verified identity.
3. `GET /media/video-v2/connections/:id/readiness` performs bounded `tools/list`, fingerprints the entire observed input/output-schema inventory, and reports safe tool names plus exact operation blockers. It invokes no unknown tool. `POST .../:id/discover` retries wallet binding only when an authoritative profile has been reviewed, then returns readiness. A wallet belonging to another owner is refused; an already-connected same-owner wallet requires the explicit reconnect flow rather than merging liabilities.
4. `GET .../:id/assets` retains the existing avatars/voices/engines arrays and adds owned-only status, blockers, generation and native creation/consent guidance. Only a reviewed authenticated catalog can return available owned assets matching the wallet/account; public, unknown, revoked, ambiguous or foreign-owner entries are excluded. A missing identity is never replaced by stock. The selected pair is checked again before submission.
5. Presenter/generated-clip preparation uses the existing exact native-credit quote, finite per-job/month limits and immutable subscription request. `preparePersonalOperation` is non-generating and checks owned Media IDs. Narration/captions/final composition have a separate typed production-manifest payload; without a reviewed fixed workflow and exact non-generating price they return `VIDEO_SUBSCRIPTION_OPERATION_UNAVAILABLE` before spending. A's production adapter must admit scene and final liabilities atomically into the same `VideoSubscriptionJob` population as direct jobs, and quote the final operation before scene spending.
6. Existing saved preflight -> launch -> receipt-bound get/resume/retry-save remains the only execution route. Every new MCP send rechecks actor/workspace/grant/generation/token and current purpose-specific policy. Launch disable blocks new work while accepted receipt polling/import can finish. Lost creates remain `submission_unknown`, reserve exposure and never retry automatically. No path falls through to an API payer.

Exact public types are in `libraries/nestjs-libraries/src/videos/video-personal-subscription.v1.ts`; provider operation enums are in `subscriptions/video-provider-registry.ts`. No shared schema or VideoModule registration changed. A owns production persistence/native chat; B owns UI. Account-specific facts still required: successful owner OAuth, authoritative wallet/workspace identity, exact owned avatar/voice and consent/availability, actual tool/input/output/eligibility profile, non-generating native-credit quote semantics, finite allowance and composition compute/storage tariff. The allowlist also accepts exactly `/agents/:threadId?videoDraftId=:id[&pieceId=:id][&videoJobId=:id]`, in that order, using bounded ASCII identifiers only. Existing media returns remain available; repeated parameters, encodings, fragments, foreign URLs and arbitrary extras are rejected. The existing workspace/member checks are supplemented by actor-owned draft/piece/job checks and the existing `AgentThreadsService.ownThread` authority through an optional injected `VIDEO_SUBSCRIPTION_RETURN_CONTEXT` port. Root owns binding this pure token in the already-global ChatModule; no ChatModule/VideoModule import cycle is introduced. Missing binding disables chat returns while media settings remain usable.

Success adds no query flags. After an authorized one-use state/session callback, a failure appends exactly one final `connectionError=VIDEO_OAUTH_REFUSED` or `connectionError=VIDEO_CONNECTION_UNAVAILABLE`. The service privately binds the context to the consumed callback error and checks ownership again before returning it; replay, wrong session, lost ownership or an arbitrary error cannot select a chat. Configured FRONTEND_URL is validated before concatenating a relative path. Callback/cache/referrer controls remain in place. A/B own authorized history restoration of the exact saved draft and removal of the three context parameters after restoration.


## Personal production submission fence

Only `production/personal-v2` subscription jobs enter the aggregate guard, inside the existing transaction immediately before accepted -> submitting. It checks the approved/non-stopped parent, actor, manifest/funding digest, accepted approval, job membership, frozen account/unit/schema and exact scene request/lineage. A scoped parent write serializes stop; a same-timestamp source update serializes a concurrent source edit without changing any source field or revision. Failed/paused/stale work performs no paid create. Already-submitted receipt polling/import bypasses this new-launch check and remains recoverable.

A final request legitimately changes from manifest-only quote to ready_assets on the same deferred job/reservation. The guard retains original account/schema/unit, requires the new native quote within the reservation, and verifies ordered owned resolved scene media against the saved asset or completed generation lineage. Source images remain source images. The final-positive regression exercises the transaction guard without invoking an unavailable/fictitious composition provider. Narration is still blocked until a real owned audio result/import contract exists; no audio is passed to the video-only importer.


The final ready_assets request also needs an immutable parent anchor. A freezes `approval.final.readyRequestDigest = videoProductionDigestV1(full ready request)` in the same transaction as awaiting_assets -> accepted, preserving the original quote/caps. The worker requires a valid lowercase SHA-256 pin and compares the full canonical tool/arguments/schema/quote request. Missing/invalid pins and changed args/tool stop before submitting; an older accepted row is never trusted by backfilling from itself. A owns the writer and repeat-freeze tests; C owns comparison and pre-send regressions.

Native quote validity is checked as a finite future expiry initially, after asynchronous HeyGen identity/authority checks, and inside the final claim transaction after the remaining checks and before submitting. Expiry does not refresh a quote, choose an API payer or stop recovery of an already-submitted receipt. Deterministic SDK/HTTP/PostgreSQL regressions advance the fixture clock in the last catalog response and inside the claim; both direct and personal presenter paths send no mutation or new quote.
