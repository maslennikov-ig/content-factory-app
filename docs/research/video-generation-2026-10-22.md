# Генерация видео через внешние API: исследование V1

> Исторический пакет до получения внешних отчётов. Текущие решения, исправленные цены и выбранные API находятся в [сверке четырёх исследований](video-generation-reconciliation-2026-10-22.md). Для реализации использовать её и редакцию 3 плана; незавершённые вопросы и прежние рекомендации ниже не являются текущими требованиями.

Проверка источников: **22 октября 2026**. Редакция 2 после уточнения владельца: упрощённый API-first процесс. Эпик `content-factory-next-zlq6`; [текущий план](../superpowers/plans/2026-10-22-video-generation.md). Документация проверена; платные генерации, качество языков, реальные списания и доступ наших аккаунтов **не проверялись**.

## 1. Принятый объём

**Заготовка → качественный промпт/сценарий → внешний API → статус → готовое видео → просмотр и скачивание.**

В V1 сохраняются два формата: обычное генеративное видео и AI-ведущий. Пользователь выбирает язык и вариант по цене/качеству. Это SaaS для разных клиентов, без предположений о личных подписках владельца. Русский — один из языков; язык интерфейса и речи независимы.

Весь результат производит внешний сервис. Собственные монтаж, таймлайн, редактор раскадровок, склейка кадров, рендерер, синхронизация отдельной озвучки и наложение субтитров исключены из первой версии. Первоначальный план этих подсистем отменён уточнением владельца; реализовывать его не нужно.

Монтаж, составные ролики и правки **на стороне провайдера** остаются возможным расширением, если есть подходящий API. Это тема исследования, а не обязательный этап запуска. Автопубликация и подключение социальных аккаунтов остаются за пределами эпика.

## 2. Что исследуем теперь

Два разных результата нельзя смешивать в одном обещании:

| Тип API | Что получаем | Как используем |
|---|---|---|
| Генерация клипа | Завершённый короткий файл с ограничениями конкретной модели | Предлагаем поддерживаемые длительность/формат/звук; не обещаем минутный составной ролик |
| Готовое видео из промпта/сценария | Провайдер сам делает ведущего, речь, сцены и сборку в поддерживаемых сочетаниях | Основной кандидат, если нужен сразу оформленный ролик |
| Редактирование видео через API | Провайдер создаёт изменённый вариант | Опционально после проверки API, цены и качества |
| Функция только в веб-студии | Нет подтверждённого программного доступа | Не выдаём за возможность нашей интеграции |

Начать с небольшого набора: один общий видеосервис, один сервис ведущего/готового ролика, если первый не покрывает оба формата. Исследовать Higgsfield, fal, Runway и Google, а также HeyGen Video Agent и альтернативы. Итоговый набор определится по качеству результата, API-возможностям и цене принятой попытки, а не количеству подключений.

**Управление агентом реально для документированных API-операций.** У Higgsfield описаны submit, request ID, status/result и cancel; готовое видео возвращается ссылкой. Это подтверждает управляемую из нашей платформы генерацию, но не доступность каждой функции Cinema Studio/редактора через API. [Higgsfield Quick Start](https://open.higgsfield.ai/quick-start), [официальный SDK](https://github.com/higgsfield-ai/higgsfield-client).

**Более полный prompt-to-video путь также есть среди кандидатов.** HeyGen документирует `POST /v3/video-agents`: сервис берёт на себя сценарий, выбор аватара, композицию сцен и рендер; есть generate/chat режимы и отдельный запрос изменения. Это заявленный API-контракт, ещё не проверенная пригодность результата для нас. [Create Video Agent Session](https://developers.heygen.com/reference/create-video-agent-session), [Request revision](https://developers.heygen.com/reference/send-message-or-request-revision).

Нужно проверить, что конкретная комбинация языка, длительности, речи/субтитров/музыки и вида ролика действительно поддерживается одним выбранным маршрутом. Если нет — выбрать другой API или показать ограничение до запуска. Не компенсировать недостаток провайдера незаметным добавлением собственного монтажа.

[Lifecycle](https://ai.google.dev/gemini-api/docs/deprecations), [выбор видеомодели](https://ai.google.dev/gemini-api/docs/video).
- **Gemini Omni 1.1 Flash**: генерация и редактирование через Interactions API. Для многоязычного V1 разумно сначала оценивать его визуальные сцены с отдельно управляемой речью. [API и ограничения](https://ai.google.dev/gemini-api/docs/omni).
- **Veo 3.1 GA в Google Cloud**: `veo-3.1-generate-001`, 4/6/8 секунд, 9:16 и 16:9, 720p/1080p/4K; референсы имеют свои ограничения. Omni тарифицируется токенами: $17.50 за миллион выходных video-токенов и 5,792 токена на секунду 720p, то есть около **$0.10136/с выходного видео**, плюс вход и прочие оплачиваемые выходы. Это не стоимость готового ролика и не доказательство, что произвольная длительность принимается API. [Тариф Gemini](https://ai.google.dev/gemini-api/docs/pricing#gemini-omni-flash).

### Ведущий, речь и сборка

**HeyGen v3 — первый кандидат для проверки ведущего.** Есть `POST /v3/videos`, получение результата и API вебхуков. Старые версии выводятся из эксплуатации на границе 31 октября–1 ноября; таблица и пример Sunset-header расходятся на день. Новый путь сразу проектировать для v3. [Версии API](https://developers.heygen.com/endpoint-version-comparison).

Цены HeyGen нельзя бездумно скопировать в продукт: help-таблица показывает Avatar V $7.20/мин, IV Digital Twin $4.83/мин и III Studio $0.99/мин; собственная статья поставщика от 20 октября приводит другие ставки. Для предварительного расчёта хранить источник и диапазон; перед допуском платного запроса получать проверяемую ставку для выбранного engine/типа аккаунта. API-кошелёк отделён от веб-подписки. 4K-файл у IV/V по help-таблице содержит увеличенного с 1080p аватара — это не native 4K. [API pricing](https://help.heygen.com/en/articles/10060327-heygen-api-pricing-explained), [противоречащая статья](https://www.heygen.com/blog/best-ai-avatar-talking-head-apis).

Альтернативы: **D-ID** — изображение + текст/аудио, асинхронный результат; **Synthesia** — сценовый Video API, но доступ по тарифу и ограничения stock-avatar использования требуют отдельной проверки. Их не нужно подключать в первый спринт только ради количества логотипов. [D-ID API](https://docs.d-id.com/reference/createtalk), [D-ID pricing](https://www.d-id.com/pricing/api/), [Synthesia API](https://docs.synthesia.io/reference/introduction), [лицензирование роликов Synthesia](https://help.synthesia.io/en/articles/6341928-synthesia-video-licensing).

**Озвучка:** ElevenLabs публикует $0.10/1,000 символов для Multilingual v2/v3 и $0.05/1,000 для Flash/Turbo; точную ставку свежих вариантов нужно связывать с моделью, а не переносить по имени бренда. Есть TTS с таймкодами. Google Cloud Standard TTS — кандидат дешёвого контроля: $4/миллион символов после бесплатного объёма. Это сравнение цены, а не естественности речи. [ElevenLabs API pricing](https://elevenlabs.io/pricing/api), [таймкоды](https://elevenlabs.io/docs/api-reference/text-to-speech/convert-with-timestamps/), [Google TTS pricing](https://cloud.google.com/text-to-speech/pricing).

Отдельный TTS и собственная сборка не входят в пересмотренный V1. Сведения об озвучке выше остаются сравнительной справкой; выбранный сервис должен сам возвращать требуемое видео с речью.

## 5. Подготовка качественного промпта

1. Из заготовки взять факты и источники, авторский замысел, аудиторию, цель и стиль бренда.
2. Подготовить компактный видеобриф: что зритель должен понять, что показать, какой язык/формат нужен, разрешённые референсы и ограничения.
3. Преобразовать бриф под выбранный API: краткий визуальный промпт для clip-модели либо сценарий/режиссёрское задание для платформы готовых роликов. План сцен может быть текстом внутри запроса провайдеру; собственный редактор сцен не нужен.
4. Дать пользователю отредактировать промпт/сценарий; проверить параметры, выбранный язык и ожидаемый расход.
5. Отправить задание, сохранить его ID, показать статус и готовое видео.
6. По обратной связи улучшить промпт и сделать новую явно оплачиваемую попытку. Использовать provider edit/revision только если этот метод действительно поддерживается; не обещать бесплатную частичную правку.

Промпт должен описывать конкретный визуальный результат, действие, референсы, стиль и требуемую речь. Не отправлять весь Telegram-пост как инструкцию к ролику. Для ведущего особенно важны точный смысл, произношение имён и длина речи. Факты связаны с заготовкой; художественный кадр не выдаётся за документальную съёмку.

Модельные правила различаются: Runway Gen-4 рекомендует короткое описание движения и положительные формулировки, тогда как end-to-end агент может принимать более подробное задание. Не переносить правила старой версии на новую автоматически. [Runway prompt guide](https://help.runwayml.com/hc/en-us/articles/39789879462419-Gen-4-Video-Prompting-Guide).

Минимально сохраняем source revision, цель, target locale, вид ролика, промпт/сценарий и его версию, выбранный provider/model и параметры, ссылки на свои референсы. Не вводим локальный timeline или граф производства отдельных сцен.

## 6. Языки, результат и минимальная надёжность

Язык исходника, интерфейса, технического промпта и речи разделяются. API без нужного языка речи не считается многоязычным только потому, что принимает английский visual prompt. Поддержку языка в каталоге и проверенное качество показывать раздельно. Нет скрытой замены языка на английский. AI-ведущий сохраняется в V1; клонирование реального человека не становится обязательным условием.

После запуска сохраняем provider request/session ID, статус, версию входа и известный расход. Закрытие браузера или повторное открытие чата продолжает проверку того же задания. Не повторяем платный submit при потерянном ответе, пока исход не выяснен. Отмена доступна в пределах реальных возможностей API; остановка polling не доказывает отмену генерации.

Файл скачивается в существующую медиатеку с проверкой принадлежности рабочему пространству и допустимости адреса/размера/типа файла. Срок жизни ссылки провайдера не должен определять срок жизни сохранённого результата. Использовать имеющиеся механизмы задач, AI-допуска и квитанций; новая универсальная финансовая система или рендер-очередь не нужны для этого эпика.

Стоимость сравниваем как сумму всех оплаченных попыток и провайдерских изменений, делённую на число принятых готовых видео. При отсутствии фактических данных показываем оценку и неизвестные. Для клипов и полностью оформленных роликов вести разные сравнения; нельзя умножить тариф восьмисекундного клипа на минуту и выдать это за подтверждённый end-to-end результат.

## 7. Проверка пользы промптов

Первый тест — исходный пользовательский запрос против подготовленного нами промпта на одинаковой модели, с одинаковыми настройками и референсами. Отдельно обычное видео и ведущий; затем представительная языковая выборка. Оценить сохранение смысла, визуальную полезность, речь, пригодность результата, количество переделок и стоимость. Внешний API выполняет всю обработку видео; собственного монтажного benchmark нет.
