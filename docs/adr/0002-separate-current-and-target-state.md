# ADR-0002: Разделять текущее и целевое состояние

**Статус:** Accepted
**Дата:** 2026-08-11

## Контекст

Репозиторий содержит работающий продукт Postiz и одновременно служит основой будущего Content Factory Next. Если описывать существующие и желаемые возможности одинаковым языком, команда начнет принимать план за реализованный контракт.

## Решение

- Архитектурная документация помечает `current`, `target`, `decision` или `runbook`.
- Current-state подтверждается ссылками на исходники, schema и configuration.
- Target-state явно называет нереализованные сущности и границы.
- Миграционная карта связывает target с существующими швами, не обещая реализацию.
- После реализации документ переводится в current только вместе с приемочной проверкой.

## Последствия

- Читатель может отличить факт от направления.
- Документация частично дублирует названия доменов в current и target разделах, но это сознательная цена ясности.
- PR/коммит, меняющий границу, обязан обновить соответствующий статус.

## Альтернативы

- Один «идеальный» архитектурный документ: короче, но вводит в заблуждение.
- Только код без target docs: не дает устойчивой программы миграции.
