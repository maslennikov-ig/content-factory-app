# ADR-0003: Версионировать Temporal contracts

**Статус:** Accepted
**Дата:** 2026-08-11

## Контекст

Temporal воспроизводит историю workflow. Недетерминированное или несовместимое изменение уже использованного workflow может сломать незавершенные и восстанавливаемые executions. В Postiz сохранены `postWorkflow` версии 1.0.1–1.0.5, а текущие вызовы используют V105.

## Решение

- Не менять несовместимо workflow/activity contracts, которые могли быть запущены.
- Новая последовательность, signal contract, activity name/payload или детерминированная ветка получает новую versioned export.
- Старые версии остаются зарегистрированными, пока retention и отсутствие активной истории не доказаны.
- I/O и недетерминированные операции выполняются в activities, не в workflow code.

## Последствия

- В репозитории сознательно сохраняется несколько похожих версий.
- Любой refactor orchestrator требует проверки replay/compatibility, а не только typecheck.
- Content Factory workflows следуют тому же правилу с первой версии.

## Альтернативы

- Редактировать workflow на месте: проще краткосрочно, но рискованно для replay.
- Использовать один общий универсальный workflow: снижает число файлов, но создает сложный и хрупкий контракт.
