# ADR-0012: Агентная обвязка — реестр действий, AI SDK поверх Mastra, свой контроллер

**Статус:** Accepted
**Дата:** 2026-09-26

## Контекст

Владелец 26.09.2026 решил переработать унаследованный от Postiz раздел «Агент» так, чтобы из чата
делалось всё, что делают экраны (эпик `content-factory-next-kcxz`, спецификация
[`docs/product/agent-harness-spec.md`](../product/agent-harness-spec.md)). Решения владельца: место
прежнее (`/agents`), автономия «почти всё сам» (платные шаги и бронь без вопроса, удаление и
подключение — с подтверждением), входы — веб и MCP.

Унаследованный агент стоит на CopilotKit 1.10.6 и `@ag-ui/mastra` 1.0.1. Эта связка не передаёт в
браузер ни подтверждение вызова инструмента, ни вопрос человеку (`suspend`) — без них автономию с
подтверждениями не построить. Разведка `kcxz.2` проверила замену на стенде с живой моделью
(27 платных операций, 0,03 USD; материалы
[`.codex/stages/content-factory-next-kcxz/evidence/spike-2026-09-26/`](../../.codex/stages/content-factory-next-kcxz/evidence/spike-2026-09-26/README.md)).

## Решение

1. **Один реестр действий.** Каждое действие продукта описано один раз и вызывает ту же службу, что
   HTTP-дверь экрана; потоковая работа читает тот же генератор событий. Права берутся из
   `@CheckPolicies` самой двери и проверяются `PermissionsService.check` — разведка подтвердила:
   EDITOR проходит, USER получает отказ `create:editor`. Из реестра строятся инструменты Mastra и
   инструменты MCP.
2. **Транспорт — AI SDK UI (`useChat`, `ai@7`) и `@mastra/ai-sdk` `handleChatStream` в нашем
   Nest-контроллере `POST /agent/chat`, контракт потока закреплён на `v7`.** Разведка доказала:
   токены идут потоком через цепочку flex, подтверждение приходит родной частью
   `tool-approval-request`, вопрос — `data-tool-call-suspended` и продолжается по `runId`, в том
   числе после перезапуска бэкенда (`listSuspendedRuns`), события службы доходят частями `data-*`.
3. **Mastra 1.7x** (core 1.71, memory 1.32, pg 1.27 на день решения). Ноль новых ошибок типов.
   Схема хранилища Mastra растёт с 27 до 43 таблиц (96 операторов, 23 из них
   `CREATE INDEX CONCURRENTLY` вне транзакции): миграцию запускает владелец отдельным шагом выпуска,
   код может выйти раньше неё. Контракт «29 таблиц `mastra_*`» в runbook становится «45».
   `@mastra/mcp` остаётся 1.x до пересборки MCP (`kcxz.26`).
4. **Нити личные**: ресурс памяти `{organizationId}:{userId}`, владелец нити проверяется до любого
   чтения.
5. **Учёт**: одна операция `agent` на запрос, где работает модель (сообщение, ответ на
   подтверждение, продолжение); история, список нитей и поиск ожидающих вопросов бесплатны. Платные
   действия идут **вне** операции хода и списывают свои операции, как их двери.
6. **Роль ИИ `agent`**, по умолчанию `openai/gpt-6-luna` на flex: на шести запросах 6/6 верных
   инструментов, как у `anthropic/claude-haiku-4.5`, при цене хода в ~40 раз ниже и сохранённом
   голосе продукта. Пересмотреть по записанному набору сценариев.
7. **Пределы хода**: не больше 6 шагов, 1 платное действие (жёстко 2), `maxRetries: 0`.
   *Поправка 28.09.2026 (живой прогон W3, P2-B):* шагов **7**, и последний разрешённый шаг — только
   слова: Mastra `prepareStep` даёт ему `toolChoice: 'none'` и строку «скажите, что сделано и что
   осталось; «Напишите «дальше» — продолжим.»», а дверь сама пишет эту строку, если поток всё равно
   кончился вызовами инструментов без слов и без карточки. Причина: ход «второй аватар по пяти строкам»
   истратил все шесть шагов на инструменты и закончился молча. Седьмой шаг возвращает шесть рабочих,
   которые были у предела; платные пределы не меняются. Подробности — спецификация §4.6.
8. **Классы риска** `read / write / paid / confirm / input / secret` по спецификации §5.1; MCP не
   получает `confirm`, `input` и `secret`.
   *Поправка 29.09.2026 (`kcxz.26`, MCP):* вход MCP — один маршрут Nest `/mcp`, Streamable HTTP без
   состояния (`startHTTP` с `serverless: true`, только POST; SSE, `/mcp-oauth` и ключ области не
   открывают MCP), протокол — прежний по умолчанию SDK (до 2025-11-25). OAuth на человека — наш
   сервер авторизации поверх продуктового OAuth (метаданные RFC 9728 и RFC 8414, регистрация RFC 7591
   только публичных клиентов, PKCE S256, `resource` привязан к коду и токенам, `iss` в ответе, доступ
   на час, обновление на 30 дней с ротацией); хранятся только хэши. Роль перечитывается из членства
   при каждом запросе; инструменты — те, что чат даёт этой роли; предел запросов — на токен.
   Подробности — спецификация §4.10.

## Поправка 27.09.2026: нативно на последней Mastra, чат плюс артефакты

Владелец 27.09: «обновимся до последней Mastra и всё сделаем под неё; за образец — Codex и Claude, обычный
чат плюс артефакты, которые открываются рядом; в Mastra это уже есть — делай нативно, не хардкодь». Разбор
исходников и документации пакетов точных версий:
[`evidence/mastra-native-2026-09-27.md`](../../.codex/stages/content-factory-next-kcxz/evidence/mastra-native-2026-09-27.md).

1. **Версии.** core 1.71.0, memory 1.32.1, pg 1.27.1, ai-sdk 1.10.5 — последние на npm на 27.09. `ai`
   7.0.118 и `@ai-sdk/react` 4.0.121 (закрепляет ровно эту `ai`). `@mastra/mcp` → **1.18.x**, не 2.x:
   2.x говорит только на протоколе MCP 2026-07-28, который внешние ассистенты ещё не поддерживают; 1.18
   умеет OAuth и подсказки инструментов на обоих протоколах. На 2.x — когда клиенты перейдут.
2. **Экран — чат плюс артефакт.** Разговор слева, артефакт (заготовка, адаптация, бронь, аватар, канал)
   открывается рядом как экран продукта. У Mastra нет своего понятия «артефакт»: нативно это сохранённая
   типизированная часть сообщения — выход инструмента с `outputSchema` или часть
   `ctx.writer.custom({ type: 'data-<вид>', data: { id, … } })`, которая с 1.7x пишется в историю нити
   (`transient: true` — только для хода работы). Карточка в разговоре и панель рядом — наш рендер этой
   части по `id`. Своего канала событий нет.
3. **Реестр строит родные инструменты Mastra**: `createTool({ title, transform, toModelOutput,
   requireApproval, suspendSchema, resumeSchema, requestContextSchema, mcp: { annotations } })`. `title` —
   подпись для экрана, `transform` вычищает служебное и секреты из того, что видят браузер и история.
4. **Проверки при вызове — в `hooks.beforeToolCall` / `afterToolCall` агента**, а не обёрткой каждого
   инструмента: повторная проверка прав CASL, предел платных действий, выход платного действия из операции
   хода, привязка одобрения к отпечатку `toolName + args`. Отказ — `declineToolCall({ reason })`, причина
   доходит до модели.
5. **Личные нити нативно**: сервер кладёт `MASTRA_RESOURCE_ID_KEY` = `{orgId}:{userId}` и
   `MASTRA_THREAD_ID_KEY` в `RequestContext`, Mastra игнорирует значения клиента; у агента
   `requestContextSchema`.
6. **Знания по разделам — навыки Mastra** (`createSkill`, `Agent({ skills })`): «Аватар», «Каналы»,
   «Контент», «План», ответы помощи раскрываются по мере надобности вместо одной огромной инструкции. Если
   каталог раздувает запрос — `ToolSearchProcessor` со `storage: 'context'`. Дешёвые обработчики
   `UnicodeNormalizer` и `SystemPromptScrubber` включены; детектор инъекций — отдельный вызов модели, только
   на вставленном чужом тексте, решение по замеру.
7. **Остаётся нашим**: контроллер `POST /agent/chat` (права, учёт, нити), экран и карточки в `cf`-токенах
   (исходником для перекраски годятся компоненты Vercel AI Elements, в том числе `Artifact`).
   Не берём сейчас: `@mastra/react` — клиент только к серверу Mastra, контекст запроса из браузера, свои
   стили; `@mastra/nestjs` 0.2.x — catch-all, глобальный `bodyParser: false` и весь API Mastra наружу,
   включая прямой запуск инструментов; `AgentController` и durable agents — Beta, одобрения живут в памяти
   процесса; Workspace и code mode — дают модели файловую систему и оболочку; `generateTitle` и
   observational memory — фоновые вызовы модели вне учёта хода.
8. **Хранилище**: схема pg 1.27.1 — те же 45 таблиц; `mastra migrate` чистит только таблицы трассировки,
   поэтому миграция остаётся нашим SQL, запускаемым владельцем. `exportSchemas()` — сверка этого SQL.

## Последствия

Обязательные требования к боевой сборке, найденные разведкой:

- параметры агента строятся только на сервере: из тела запроса берутся `messages`, `resumeData`,
  `runId` — `handleChatStream` иначе примет от клиента память, контекст запроса и пределы;
- ошибки проходят через `onError` в коды продукта: по умолчанию клиенту уходил стек и пути файлов;
- ход, закончившийся частью `error`, отмечается в учёте как неудачный (сейчас записывается
  `succeeded`);
- платные действия выходят из операции хода явно, со стражем: по умолчанию их вызов молча
  поглощается операцией `agent` и недоучитывается;
- клиент продолжает то же сообщение ассистента при ответе на подтверждение и продолжении и при
  перезагрузке поднимает историю вместе с ожидающими вопросами;
- после одобренного действия агент говорит, что сделано (Luna ответила «подтвердите»).

Положительное: одна реализация на экран, чат и MCP; права не расходятся по построению; CopilotKit и
`@ag-ui/mastra` уходят из экрана агента. Отрицательное: `ai` сменил v5 → v7 за год — контракт
закреплён, транспорт сосредоточен в одном контроллере; миграция хранилища Mastra — самый рискованный
шаг эпика, для неё премортем `kcxz.4`.

## Альтернативы

- **CopilotKit ≥ 1.61.2 + `@ag-ui/mastra` 1.1.x.** Тройное согласованное обновление; `suspend`
  передаётся как interrupt, а `requireApproval` не передаётся вовсе.
- **Свой NDJSON-протокол.** Повтор логики подтверждений, продолжений и состояний частей, которую
  `@mastra/ai-sdk` уже ведёт.
- **Сервер Mastra в Nest (`@mastra/nestjs`).** Маршрут catch-all мимо CASL и `AiUsageService`.
- **Отдельные инструменты с копией логики дверей.** Права и поведение чата и экранов разойдутся.
- **Модель `anthropic/claude-haiku-4.5` для роли `agent`.** Не точнее на проверенном наборе,
  дороже в ~40 раз, теряет голос продукта.
