# Architecture Decision Records

**Статус:** `decision index`

ADR фиксирует решение, которое будет дорого или неоднозначно восстановить из кода. Он не заменяет план реализации и не используется как журнал задач.

## Когда нужен ADR

- выбор платформенной/доменной границы;
- смена хранилища или модели tenancy;
- новый публичный контракт или способ совместимости;
- решение по лицензированию и распространению;
- изменение durable execution strategy;
- решение, затрагивающее несколько вертикальных срезов.

Локальная реализационная деталь с очевидным обратимым выбором ADR не требует.

## Шаблон

```markdown
# ADR-NNNN: Короткое решение

**Статус:** Proposed | Accepted | Superseded
**Дата:** YYYY-MM-DD

## Контекст
Какая проблема и ограничения существуют.

## Решение
Что именно принято.

## Последствия
Положительные, отрицательные и обязательные действия.

## Альтернативы
Какие реалистичные варианты рассмотрены и почему не выбраны.
```

Новый ADR получает следующий номер. Старый принятый ADR не переписывают задним числом: его заменяют новым и отмечают `Superseded by ADR-NNNN`.
