# Применение схемы правок автора к боевой базе

**Эпик:** `content-factory-next-pl1`, задача `pl1.32`.

**Что применяется:** одна новая таблица `BrandVoiceEdit` — пара «что предложил
продукт / что отправил человек», привязанная к аватару и к версии голоса,
которой написан черновик. Четыре индекса и два внешних ключа.

**Проверенный текст операторов:**
[`voice-edits-schema-apply.sql`](./voice-edits-schema-apply.sql). Семь
операторов. **Ни одного `DROP`, ни одного `TRUNCATE`, ни одного изменения
существующей таблицы** — только создание новой. Это первое применение схемы
этого эпика, которое проходит через стража без единого исключения.

---

## Главное предупреждение, оно же прежнее

`prisma migrate diff` против базы выдаёт эти семь операторов **вместе с
`DROP TABLE` по каждой таблице `mastra_*`**, которых нет в `schema.prisma`.
Применять его вывод целиком нельзя, и `prisma db push` нельзя тем более.

На 27.08.2026 таблиц `mastra_*` в базе продукта нет — разделение выполнено
21.08.2026, см. [`runtime-roles-mastra-split-plan.md`](./runtime-roles-mastra-split-plan.md).
Проверять это надо каждый раз: диагноз недельной давности не является
состоянием базы сегодня. На базе стенда их 27, и там же этот текст проверен.

## Порядок

```bash
# 1. Сколько таблиц Mastra в базе сейчас
psql "$DATABASE_URL" -tAc \
  "select count(*) from information_schema.tables where table_name like 'mastra_%'"

# 2. Предпросмотр — читать, не применять
npx prisma migrate diff \
  --from-url "$DATABASE_URL" \
  --to-schema-datamodel libraries/nestjs-libraries/src/database/prisma/schema.prisma \
  --script > /tmp/diff.sql

# 3. Страж: выбранный текст обязан быть подмножеством того, что печатает diff
node scripts/operations/validate-prisma-migration-sql.cjs \
  --diff /tmp/diff.sql \
  --selected docs/operations/voice-edits-schema-apply.sql \
  --mode update --allow-table BrandVoiceEdit

# 4. Применить только проверенный текст, одной транзакцией
psql "$DATABASE_URL" --single-transaction -v ON_ERROR_STOP=1 \
  -f docs/operations/voice-edits-schema-apply.sql

# 5. Тот же счёт, что и в шаге 1
psql "$DATABASE_URL" -tAc \
  "select count(*) from information_schema.tables where table_name like 'mastra_%'"
```

Шаги 1 и 5 обязаны дать одно и то же число.

## Почему транзакция снаружи, а не внутри файла

В файле нет `BEGIN`/`COMMIT`, и это не забывчивость. Страж
`validate-prisma-migration-sql.cjs` знает операторы схемы и не знает ключевых
слов транзакции: файл с `BEGIN;` он отвергает как неизвестную операцию, то есть
проверить его не может вовсе. Транзакцию даёт `psql --single-transaction` —
результат тот же, а текст остаётся машинно проверяемым. Файл, который страж не
может прочитать, стражем не прикрыт.

`avatars-schema-apply.sql` от 25.08.2026 несёт `BEGIN`/`COMMIT` именно поэтому:
его страж и так отверг из-за `DROP INDEX`, и применялся он руками по решению
владельца.

## Применено на боевой базе

28.08.2026, выпуск `5affd674a3fd`. Таблиц в схеме `public` 71 → 72, `mastra_*`
`0` → `0`, таблица пуста, повторный `migrate diff` печатает `This is an empty
migration.` Страж прошёл против **настоящего** расхождения боевой базы, а не
только против стенда: предпросмотр вернул ровно эти семь операторов и ни одного
`DROP`.

Три вещи, которые этот порядок выше описывает не полностью:

- **Применять от owner-роли.** Права раздаются через `ALTER DEFAULT PRIVILEGES
  FOR ROLE <owner>` (`bootstrap-app-db.sh`), поэтому таблица, созданная любой
  другой ролью, приложению видна не будет. После применения проверено запросом
  к `information_schema.role_table_grants`: у `*_runtime` ровно `SELECT,
  INSERT, UPDATE, DELETE`.
- **Предпросмотр не с рабочей машины.** У боевого Postgres нет host-порта.
  Контейнер из нового образа поднимается в сети `content-factory-next_internal`
  с `--env-file /srv/content-factory-next/app.env`, и `prisma migrate diff`
  идёт оттуда.
- **`docker --env-file` не снимает кавычки.** `DATABASE_URL="postgresql://…"`
  приезжает внутрь вместе с кавычками, и Prisma отвечает `P1013 — the scheme is
  not recognized`. Кавычки снимаются в скрипте, который монтируется в контейнер
  файлом: цепочка `ssh → sh → docker → sh` съедает любое экранирование, и
  бороться с ней в одну строку бессмысленно.

## Что эта таблица собирает и чего не делает

Пару текстов на одно сохранение поста: черновик продукта и то, что человек
отправил вместо него. **На генерацию не влияет ничего из этого** — ни на промпт,
ни на порог, ни на примеры, — и это держится красной проверкой
`tests/brand-voice.edits.test.cjs`. Порядок работ строгий: сначала собирать и
мерить, потом прогон на стенде той же меркой, и только после положительного
ответа — подмешивать.

Срок хранения назван в политике конфиденциальности (раздел 2.2 и пункт в
разделе 6, все шестнадцать языков, редакция 27.08.2026): пара живёт, пока живёт
аватар, и удаление аватара удаляет её сразу. В коде это `onDelete: Cascade` плюс
явное стирание в `VoiceService.deleteAvatar`; на удалении аватара правки
наследнику **не** переходят, в отличие от корпуса.
