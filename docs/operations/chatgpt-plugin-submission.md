# Подача remote MCP в каталог ChatGPT и Codex

**Состояние готовности:** 01.10.2026. Это контракт подготовки и проверки. Документ не означает, что приложение подано, одобрено или опубликовано.

OpenAI сейчас описывает публичную подачу как remote MCP plugin через Plugins Directory. Это общий каталог ChatGPT и Codex. Путь включает ZIP-пакет, подключение и проверку MCP, отправку на review и отдельную публикацию после одобрения. Это отличается от локального подключения сервера в Developer mode.

## Предварительные условия

До подачи владелец выбирает OpenAI-организацию и проект, под именем которого публикуется приложение, и лично проверяет в Dashboard:

- у подающего есть `api.apps.write`; для просмотра черновика и статуса ревью нужен `api.apps.read`. Владелец организации получает оба права автоматически; остальные пользователи должны получить права от владельца;
- имя издателя подтверждено в OpenAI Platform как индивидуальное или бизнес-имя. Неподтверждённое имя приводит к отклонению;
- у выбранного проекта глобальный регион хранения данных. Проекты с EU data residency сейчас не допускаются к подаче remote MCP;
- владелец действительно хочет публичную доступность приложения в выбранных при подаче странах.

Для ревью требуется отдельная учётная запись для проверяющих, если интеграция требует входа. Она должна открываться по публичному URL и работать без MFA, SMS/e-mail-кода, magic link, частной сети или дополнительного ручного согласования. Используются тестовые данные, а не аккаунт реального пользователя. У учётной записи должны быть права и данные для всех сценариев. Её секреты вводятся только в защищённое поле Review details в Dashboard и не попадают в ZIP, Git, этот документ или публичный пакет.

В demo-пространстве нужны тестовые заготовки, поводы и подключённый ручной канал без реальной публикации. Часть положительных сценариев выполняет платную генерацию или поиск. До их запуска владелец должен определить, чей лимит AI расходуется и какой предел применён. Величина лимита и учётные данные здесь не заданы. Платные сценарии не запускались.

## Текущий endpoint, домен и scan

Для подачи OpenAI требует публичный стабильный HTTPS MCP endpoint, который не является локальным или тестовым. Обычно используется универсальный URL для всех организаций; шаблонные URL подходят только для отдельных рабочих пространств и trusted developers с согласованной OpenAI схемой.

После входа в Dashboard владелец подключает server, проходит показанную там проверку домена и запускает Scan Tools на production endpoint. Для проверки домена точный выданный порталом токен публикуется как простой текст по созданному адресу `/.well-known/openai-apps-challenge` на MCP-домене или разрешённом родительском домене; затем Verify Domain должен пройти. Токен берётся только из принадлежащей владельцу сессии Dashboard, не придумывается и не записывается в открытые материалы.

Scan Tools — источник истины для опубликованного списка: он считывает имена и описания инструментов, схемы входа и выхода, схемы безопасности, metadata, annotations, инструкции сервера и metadata UI, если они есть. Перед подачей требуется успешный актуальный scan production-сервера.

Каждый фактически просканированный инструмент должен иметь точные `readOnlyHint`, `destructiveHint` и `openWorldHint`. В форме приводится отдельное обоснование значений аннотаций каждого инструмента. Локальная таблица риска в `libraries/nestjs-libraries/src/chat/capabilities/mastra.adapter.ts` показывает, что аннотации уже формируются в коде; это не доказывает, что текущий production scan их получил или что каждое значение/обоснование будет принято. Нужны сверка с фактическим scan и проверка поведения по каждому инструменту.

Текущий поиск исходников backend, orchestrator и shared libraries не обнаружил UI template/resource metadata MCP. По текущей реализации CSP и скриншоты не выглядят обязательными: официальное требование о CSP относится к MCP, который возвращает UI; портал разрешает скриншоты только когда scan обнаруживает UI template. Это предварительная локальная оценка. Если production scan обнаружит UI, добавить точные домены CSP и объяснения, затем повторно оценить материалы.

## Пакет и поля подачи

В текущем официальном процессе remote MCP включается в начальный ZIP-пакет; сервер нельзя добавить позднее к уже поданной версии только со skills. В репозитории при проверке не найдено `plugin.json`, `mcp.json` или `.mcp.json`, то есть подготовленного к загрузке пакета пока нет.

В официальном примере переносимого Agent Plugins пакета используются корневой `plugin.json` и корневой `mcp.json`. В манифесте OpenAI-specific listing, review и publication fields лежат под `extensions.com.openai`; MCP manifest содержит `mcpServers` с типом Streamable HTTP и URL. Для Codex compatibility описан `.codex-plugin/plugin.json` с `.mcp.json`. Для текущей подачи выбрать формат после сверки с Upload flow; не добавлять `apps`/`.app.json` references или lifecycle hooks, которые текущий портал не принимает. Все значения для publisher, domain и endpoint должны происходить из действительных владельческих настроек.

Портал требует имя, основной app icon, описание, URL компании/сайта и URL политики конфиденциальности, сведения MCP/инструментов, тестовые запросы и результаты, сведения о локализации и странах доступности. Ограничения текущего error reference: display name — до 30 знаков, subtitle — до 30, длинное описание — до 4 000, developer name — до 80; отдельная capability — до 120 знаков. Поля примеров манифеста не считать обязательными, если портал/схема этого не требует. Поддержка/Terms URL остаются среди отложенных юридических сведений; проверить их обязательность в текущей форме, не заполнять догадками.

Стабильное имя и описания должны соответствовать продукту и подтверждённому издателю, точно объяснять функциональность и не создавать впечатление одобрения OpenAI. Guidelines требуют законченный продукт; demo или trial plugin не принимается. Если MCP scan не показывает UI, скриншоты не включать. Пароли, reviewer credentials, API keys и другие секреты в публичный ZIP не включать.

## Сценарии для review

Официальная форма требует ровно пять положительных и три отрицательных тест-кейса для первичной MCP-подачи. Положительные кейсы содержат описание, prompt, имена ожидаемых tools и наблюдаемый expected behavior. Отрицательные кейсы описывают запрос, на который нельзя действовать, причину и ожидаемый отказ, уточнение или безопасный fallback.

Ниже — черновые сценарии по локальному каталогу Content Factory. Имена tools — кандидаты по текущим идентификаторам исходника. Перед загрузкой заменить/подтвердить их точными именами из актуального Scan Tools. Каждый положительный сценарий должен быть исполнен на reviewer account, а ожидаемый результат уточнён на его seeded sample data. Пока этого нет, ни один кейс не считается проверенным.

| Тип | Запрос для теста | Ожидаемые инструменты | Ожидаемое наблюдаемое поведение |
| --- | --- | --- | --- |
| Положительный 1 | «Покажи новые поводы. После моего выбора возьми один в работу и создай из него заготовку». | `ideas.queue`, `ideas.take`, `piece.create` | Используется выбранный повод из текущего пространства; заготовка сохраняет исходную ссылку, а человек получает понятное сообщение, из какого повода она создана. |

Если размещаются file attachments или ссылки на ожидаемые результаты, они должны быть доступны reviewer account и не содержать конфиденциальных данных.

## Неразрешённые зависимости и граница готовности

Владелец отложил юридические и операторские факты, включая регион проекта, сведения о компании, URLs поддержки, Terms и Privacy. Эти значения не заполняются предположениями. Текущая английская Privacy page раскрывает получение prompts, post text и search queries поставщиками AI API при включённой пользователем функции, но не описывает ChatGPT/Claude как внешние MCP-клиенты. До публичной подачи владелец юридически утверждает требуемые раскрытия и проверяет, что политика покрывает категории пользовательских данных, которые сервер отдаёт вызывающему ассистенту.

Также не подтверждены аккаунтные права/верификация издателя, глобальный data residency выбранного OpenAI-проекта, доступность Developer mode в owner-аккаунте, demo-account credentials и решение об AI-лимите для тестов. Не создан пакет, не получен domain challenge, не запускался production Scan Tools, не записано видео, тест-кейсы не прогонялись. Эти состояния не являются ошибками кода; без них подача не готова.

Для kcxz.46 доказательством остаётся фактический проход через ChatGPT на текущем production с записанными результатами и согласованными симптомами/исходами. Владелец делегировал проверку агенту; для исполнения всё равно нужна доступная авторизованная сессия ChatGPT. Проверка Claude.ai снята владельцем с текущей приёмки. Для kcxz.48 создание ZIP или локальная проверка не равны подаче: точка подтверждения подачи — Case ID и статус в Dashboard; публикация возможна только после отдельного одобрения и выбора владельца **Publish**. До этого проект остаётся непубликованным в каталоге.
