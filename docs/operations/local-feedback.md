# Быстрые локальные проверки

Задайте `HARNESS_REPO` — путь к установленному Dash Harness. Команда вызывает его runner с `--repo`; действующий механизм проверки выпуска проекта сохраняется.

Для правки проверки места на сервере достаточно офлайн-тестов с подменёнными
командами SSH и Docker. Они не подключаются к серверу и не публикуют образ:

```bash
python3 "$HARNESS_REPO/scripts/orchestration/run_dev_check.py" --repo "$PWD" \
  --manifest scripts/orchestration/dev-checks/capacity.json --timeout-seconds 120
```

Команда запускает выбранные Jest-тесты один раз, возвращает короткий JSON и
путь к полному локальному логу. Это проверка для разработки; общий выпуск
по-прежнему проходит полный `pnpm test` и получает receipt для точного HEAD.

Перед дорогой сборкой runtime-образа:

```bash
python3 scripts/release/check-local-build-capacity.py --min-free-gib 12
scripts/release/build-local-image.sh <tag> --min-free-gib 12
```

`12` — пример явно выбранного запаса для планируемой сборки, а не измеренный
пик потребления и не гарантия успешной сборки. Выберите запас для своего
изменения. Проверка измеряет доступные байты и inode через временный контейнер
на файловой системе выбранного локального Docker-сборщика. Свободное место
дистрибутива WSL и место на сервере не заменяют это измерение.

Поддержан локальный одноузловой сборщик с драйвером `docker`. Другой драйвер,
удалённый endpoint, ошибка измерения или нехватка места останавливают сборку.
Для измерения нужен уже сохранённый локально `alpine:3.20` с `sh` и `df`;
`--helper-image` позволяет выбрать другой сохранённый образ. Образы не
скачиваются. Проверка удаляет только свой временный измерительный контейнер;
сборочный кэш, образы и чужие контейнеры не очищаются.

Build-wrapper принимает только подготовленный публичный клон и сначала
выполняет существующие проверки receipt и архива точного исходного коммита.
Собирайте из подготовленного публичного дерева и сохраняйте порядок
`make-source-archive.sh`, проверки выпуска и публикации из
[инструкции развёртывания](production-deploy.md). Новый build-wrapper выполняет
только локальную сборку и не даёт права публиковать или развёртывать её.
