# Durable external video production revisions

Stream C extends the accepted social-factory plan. A production revision is an immutable source-bound ordered scene manifest. New drafts create a new revision, and approval pins its digest, actor, exact scripts/settings, asset identities, provider/payer and total reservation ceiling. Source/asset changes invalidate preflight. Approval never grants a different payer or raises configured limits.

The existing VideoGenerationJob remains the sole billable operation engine. Presenter/clip/narrated-scene generation and final external composition are separate intents. VideoProductionRevision stores references to those jobs, not a duplicate receipt/billing/lease engine. Production-only jobs carry an explicit productionRevisionId, an empty draftId and snapshot.kind=production/v1; legacy draft/job lists omit them, and their public view returns draftId=null. Existing Temporal contracts remain valid; the additive production workflow coordinates already persisted jobs.

Scene fingerprints bind the production identity, exact scene input, locale/output settings and owned asset identities. Unchanged completed scenes reuse the same job and Media; an uncertain scene must reconcile rather than generate again. Explicit scene generationAttempt changes create a new reviewed intent. Final composition freezes actual owned outputs and their measured durations; exact speech is never cropped to an estimated script target. Already accepted generation costs remain attached to old intents.

Higgsfield supplies validated short clips. Existing HeyGen single-video presenter generation provides reusable presenter scenes. Studio supports narrated images for faceless scenes, but a missing route/account price remains a launch blocker; public avatar rates do not establish Studio composition or narrated-image billing. Hyperframes accepts an authored deterministic HTML bundle for external final composition and has a documented target-duration public estimate. It does not synthesize narration. Owned narration or a verified generation route is required; no silent video is presented as a finished spoken video.

Admission reserves existing configured per-job ceilings transactionally, aggregates the shared VideoGenerationJob ledger by provider/payer, preserves unresolved earlier-period exposure and applies the approved cross-provider production ceiling. An estimate is not an invoice or provider-enforced ceiling. Caption cues are rejected at manifest validation when captions are disabled, before any paid scene. Unknown charges remain reserved after submit uncertainty, cancellation or storage failure. Preflight may show blockers; approval cannot override unavailable price, key, account identity or provider capabilities.

Stopping a revision prevents its unsubmitted external actions. A transaction serializes the stop against the existing engine's submitting claim; already claimed external operations can incur costs and still finish/save. A stopped revision retains all receipts and media. Native recovery reads/saves already submitted production jobs; it never submits untouched production jobs. A save failure pauses those untouched jobs under needs_attention, preserving accepted state and reservations until an explicit save retry resumes the revision. A pause racing the submission claim voids the unstarted admission without marking the scene failed. Provider status age is measured from submission, so time spent paused is not treated as an uncertain provider operation. New workflows recover dispatch gaps, coordinate completion and expose failure/unknown states; reads/import retries use existing job receipts and never submit another generation.

Focused acceptance covers immutable/CAS revisions, source and tenant isolation, atomic concurrent admission, exact selective reuse, cross-period unknown exposure, stopped revisions, interrupted submission, failed import retry, actual timing and finished artifact references. Local fixtures prove engineering only. Real RU/EN short/6–8-minute output, intelligible speech, captions, continuity, provider charges and a targeted scene revision remain the actual pilot gate.

## Owned result metadata and caption evidence

Production results expose width/height and movie duration from actual MP4 bytes, with a SHA-256 digest and `metadataStatus=measured`; unsupported or ambiguous containers have `metadataStatus=unavailable` and no invented dimensions/duration. Track rotation is applied to display dimensions. `storedFile` retains the measurement for new imports; older owned results are measured and cached under a scoped result lease. No renderer, transcoder or manifest/provider duration is used to produce this metadata. Atom layout follows Apple's [track header](https://developer.apple.com/documentation/quicktime-file-format/track_header_atom) and [movie header](https://developer.apple.com/documentation/quicktime-file-format/movie_header_atom) documentation.

Caption evidence distinguishes a provider-confirmed captioned file, exact submitted timed cues, retained verified scene lineage and unverified wishes. Actual provider SRT/VTT files and exact timed cues can become bounded validated owned subtitle Media. Cues are checked against measured file duration. No script-to-estimated-timestamps conversion is performed. Subtitle records are attached atomically to the existing completed job, reused on reload and tenant-scoped; deleted subtitle Media are not returned. Generic user-upload MIME allow-lists remain unchanged. B/A must retain needs_revision when required measured metadata, verified caption evidence or actual subtitle assets are unavailable. Provider speech accuracy and cloud quality remain separate actual-pilot criteria.
