# План: Telegram content pipeline MVP

> Актуализация namespace от 2026-08-14: текущий import alias —
> `@contentfactory/*`; на момент выполнения этого плана он ещё был вне его
> области и позднее мигрирован отдельной задачей.

**Цель:** закрыть доказательствами всю открытую часть `content-factory-next-ja3`, включая общий веб-поиск, и оставить проверенное незакоммиченное дерево.

**Подход:** один корневой владелец и одна общая граница приёмки. Работа идёт по зависимостям Beads; каждая задача переводится в `in_progress` до кода и закрывается только после сфокусированного доказательства. Платные вызовы, реальные публикации и внешние записи не входят в автономную часть и требуют отдельного вопроса перед точным действием.

**Не входит:** смена поискового вендора по умолчанию; второй вендор; новые тяжёлые зависимости; изменение совместимых `@contentfactory`, Prisma, Temporal, provider, OAuth или public API идентификаторов; commit, push, PR и deploy.

**Documentation:** `no external/versioned boundary` для текущей архитектуры — контракты заданы Beads и кодом. Для конкретного API зависимости перед использованием выполняется `docs-resolve` по её версии.

## Наблюдаемая приёмка

- Given русский пост о международной теме, When запускается исследование, Then основной запрос английский и источники международные.
- Given тема российского рынка, When запускается исследование, Then к английскому добавляется запрос на языке предмета, а справка объединяет оба набора источников.
- Given две организации с разными настройками поиска, When они генерируют одновременно и одна меняет настройку, Then конфигурации не смешиваются и новая настройка применяется без рестарта.

## Реестр объёма

Неизменяемые тексты всех 22 открытых критериев находятся в `.codex/goals/content-factory-next-ja3/scope-criterion-snapshot.json`; манифест стадии связывает их одним digest. Раскладка по волнам не меняет формулировки критериев.

### Волна 1: разблокировать создание контента

**Beads:** `ja3.2`, `ja3.4`, `ja3.3`, затем сохраняемый выбор `ja3.9`.

**Граница:** CORS и явная ошибка конфигурации Copilot; язык как явный DTO/контекст для generator, copilot, chat и autopost; длина по возможностям целевого провайдера; язык по умолчанию виден и изменяем.

**Проверка:** TDD-required — пользовательское поведение, DTO/промпты и настройки состояния. Сфокусированные Jest/TypeScript проверки плюс локальный HTTP/browser trace без платного вызова; реальный текст/изображение — отдельная точка разрешения.

### Волна 2: единая поисковая вертикаль

**Beads:** `ja3.23` → `ja3.24` → `ja3.25`, затем `ja3.26`, `ja3.27`, `ja3.29`.

**Граница:** добавочная per-organization конфигурация и зашифрованный ключ; один `WebResearchService`; английский основной и условный локальный запрос; структурированный результат; generator/chat/copilot consumers; сохранение и показ источников.

**Проверка:** TDD-required — миграция, tenancy, секреты, кэш, общий контракт и persistence. Две организации, параллельные запросы, cache reset/TTL, выключенный поиск, локальная/международная тема и round-trip источников.

### Волна 3: источники, автопост и расписание

**Beads:** `ja3.5`, затем `ja3.28` и `ja3.6`.

**Граница:** существующий безопасный RSS-путь и версионно совместимый планировщик; поиск перед переписыванием только по флагу и не для дословной публикации; неделя русских записей в календаре.

**Проверка:** TDD-required для логики и состояния; локальный RSS fixture, throwaway Temporal/Postgres, без живой публикации. Реальный AI-вызов — отдельная точка разрешения.

### Волна 4: оставшиеся открытые поверхности эпика

**Beads:** `ja3.8`, `ja3.10`, `ja3.11`, `ja3.13`, `ja3.14`, `ja3.15`, `ja3.16`, `ja3.17`, `ja3.18`.

**Граница:** полнота RU/EN и список локалей; корректные приватные Telegram-ссылки; запрет новых `text-white`; честная статистика; единый владелец Telegram update queue; снимки подписчиков; локальная производственная аналитика; комментарии discussion group.

**Проверка:** TDD-required для пользовательских дефектов, persistence, очереди и аналитики. UI-изменения используют текущие `cf-*` токены; внешний дизайн-вариант не выбирается.

### Финальная приёмка

После сфокусированных доказательств и закрытия соответствующих Beads выполнить ровно один общий набор: `pnpm run build`, `pnpm test`, `node scripts/branding/brand-scan.cjs`, `pnpm run docs:check`, `scripts/orchestration/run_process_verification.sh`, `git diff --check`. Затем обновить handoff, документацию и локальный Graphify; никакого commit/push.

## Премортем и восстановление

Verdict: **GO WITH CONDITIONS**.

- Риск смешения организаций: ключ всех кэшей — `organizationId` плюс identity конфигурации; проверка двумя параллельными организациями.
- Риск утечки ключа: шифрование существующим `AuthService.fixedEncryption`, DTO ответа никогда не содержит расшифрованный ключ.
- Риск скрытых платных вызовов: выключенная/неполная настройка завершается понятной локальной ошибкой до сетевого клиента.
- Риск несовместимого развёртывания: схема только добавочная и nullable/defaulted; миграция проверяется на throwaway базе.
- Риск Telegram single-consumer queue: connect и реакции/комментарии получают одного владельца очереди, а не второй long-poller.
- Риск Temporal: использованный upstream-контракт не меняется; при необходимости добавляется версионный преемник.
- Ошибка исполнителя: каждый критерий остаётся привязан к снимку Beads; запрещены молчаливый defer и новые `TODO/FIXME/HACK/XXX`.

Откат до приёмки — по ограниченным группам файлов в незакоммиченном дереве; чужие исходные изменения сохраняются. Для добавочных данных — roll-forward/удаление новых необязательных записей, без изменения старых строк.
