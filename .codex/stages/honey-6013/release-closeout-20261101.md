## Cold approval replay correction

The full-suite/calendar run reproduced a real defect: a cold native Session
re-evaluated an older parked approval under a newer allow policy and executed it
without an explicit answer. Before binding/subscribing, the adapter reads native
suspended runs and temporarily preserves ask for those exact owned pending gates.
Native arming removes the temporary restriction; current deny remains authoritative.
The adapter does not write permission preferences or introduce another run store.
The public Session policy method is wrapped because the SDK rule resolver is for
persisted preferences and has no replay-scoped decision hook. Native snapshot reads
return all matching runs by default. Approval responses bind the tool name to the
owned current native snapshot and recheck deny before both native response paths.

The SDK decision is not atomic with a simultaneous later policy edit inside its
asynchronous execution; domain authorization checks remain authoritative. During
replay, a same-tool call in the same thread can briefly wait until the older gate
is armed because the native policy callback exposes tool/thread, not run/call.
These are bounded native API limits, not extra task orchestration. The unchanged
cold-policy integration must pass both ordinary and shifted-calendar execution.
CI explicitly prepares the isolated research probe's PostgreSQL and Redis images;
tests never pull dependencies while executing or connect to live local databases.
