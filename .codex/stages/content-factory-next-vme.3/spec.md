# Спецификация стадии: эксплуатационная готовность

## Результат

Три проверки перестают быть условно зелёными. Docker-backed контракты получают
обязательный CI runner; browser-error relay изолирует бюджеты клиентов без
расширения принимаемого или сохраняемого payload; решение по знаку YouTube
имеет проверяемый первичный провенанс либо явно сохраняет vetted raster.

## Принятые границы

- Локальный runner без Docker может пропустить тяжёлые execution suites только
  с точной причиной. Выделенный Docker-capable CI job обязан падать при
  отсутствии Docker и запускать обе shell-проверки миграции/восстановления.
- Relay не принимает и не сохраняет IP, User-Agent, cookies, URL/query,
  пользовательский или модельный контент. Изоляционный ключ короткоживущий,
  не становится аккаунтным или межсессионным идентификатором и не попадает во
  внешний error payload.
- Знак YouTube не перерисовывается и не перекрашивается. Доверяется только
  неизменяемому первичному источнику с SHA-256; иначе текущий vetted raster
  остаётся намеренным решением с документированной причиной.
- Production scripts, production host, credentials, deploy, paid calls и
  реальные пользовательские сообщения не входят в стадию.

## Technical premortem

Verdict: **GO WITH CONDITIONS**. Откат — удаление локальных stage-коммитов;
данные и production state не меняются.

| Риск | Сигнал | Обязательная защита |
| --- | --- | --- |
| CI зелёный из-за `describe.skip` | Docker job завершён без реальных suites | fail-closed preflight и исполняемый contract-test job |
| один клиент исчерпал общий relay budget | независимый клиент получает 429 | RED/GREEN на два ключа и ограниченный lifecycle |
| скрытая идентификация клиента | ключ попал в body, log или внешний payload | закрытая схема payload и тест отсутствия запрещённых полей |
| подмена официального знака | байты/источник нельзя воспроизвести | immutable URL + SHA-256 или зафиксированный raster decision |
| исполнитель затронул production scripts | diff включает operational production path | write-zone guard и корневая проверка diff |

## Проверка и восстановление

Каждый поток сначала наблюдает свой RED, затем делает минимальный GREEN.
Корень проверяет все артефакты, неизменность production scripts, focused
контракты и один release-набор. Любая регрессия откатывается локальными
коммитами стадии; внешние данные, очереди и кэши отсутствуют.
