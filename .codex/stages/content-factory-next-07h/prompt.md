## Делегирование

Работы больше, чем помещается в одно контекстное окно. Крупные куски отдавай субагентам через
Agent tool — иначе к утру контекст кончится на середине.

Что делегировать: стадии B и C целиком, по задаче на агента. У каждой своя зона записи, свой
слой и своя проверка — они не конфликтуют.

Что оставлять себе: чтение спецификации, решения, затрагивающие несколько задач сразу, сведение
результатов, финальные проверки и закрытие задач в Beads.

Каждому субагенту давай: номер задачи, путь к спецификации, зону записи, чем проверяется
результат, и когда останавливаться. Не выдавай субагентам права на закрытие задач в Beads —
это делает корневой сеанс.

**Правило Beads, из-за которого закрытия теряются.** Запуск любого субагента дёргает `bd prime`,
тот делает `bd dolt pull`, и ранее закрытые задачи возвращаются в `open` вместе с причинами
закрытия. Поэтому: не закрывай задачи, пока работают агенты. Сначала доведи весь код, дождись
всех агентов, и только потом одной партией закрой всё, сразу сделай `bd backup sync` и **сверь
каждую задачу поимённо через `bd show`** — вывод самой `bd close` рапортует успех и до отката,
ему верить нельзя. Причины закрытия держи в черновике до подтверждения.

## Как работать

- Тест сначала, красный до зелёного. Экраны эпика `36r` **не перерисовываются**: расхождение с
  макетом — находка для отдельной задачи, а не повод править на ходу.
- Контур: DTO → Controller → Service/Manager → Repository, Prisma, без сырого SQL. Образец —
  реестр источников: `content-source.controller.ts`, `source-registry.service.ts`,
  `source-registry.repository.ts`.
- Перед тем как писать компонент, посмотри, нет ли уже такого. Второй экземпляр одного решения —
  дубликат для извлечения, а не образец для продолжения.
- Страж должен проверять вещь, а не слово. В эпике `36r` это сломалось четыре раза: файл падал за
  то, что документирует правило, которое соблюдает. Проверяй импорты, JSX и вызовы, а не
  подстроки.
- Документацию по версионно-зависимому поведению зависимостей бери через Docs L1/L2:
  сначала `@neuledge/context` с версией из lockfile, Context7 или первоисточник — только когда L1
  не отвечает.
- Запускай проверки изменённой поверхности по ходу и
  `scripts/orchestration/run_process_verification.sh`; полный объявленный набор — на закрывающей
  задаче `07h.13`.
