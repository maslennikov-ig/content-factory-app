# План: несколько способов входа

## Решение

Добавить аддитивную `UserIdentity` с глобальной уникальностью пары провайдер/идентификатор и связью с `User`. Поля `User.providerName/providerId` остаются основным способом для совместимости. Вход сначала ищет новую личность и временно использует legacy-поля как безопасный fallback до отдельного переноса данных.

Для `LOCAL` идентификатором служит нормализованный email: существующий `providerId` у локальных аккаунтов пуст, поэтому его нельзя безопасно сделать уникальным. Добавление пароля к внешнему аккаунту создаёт `LOCAL`-личность, а отвязка `LOCAL` при наличии другого способа удаляет личность и пароль. Внешняя личность добавляется только из аутентифицированной настройки аккаунта и никогда по совпадению email.

## Риски и условия

- Захват аккаунта: link endpoint принимает текущего пользователя из сессии, проверяет провайдера через существующий adapter и полагается на уникальность БД; конфликт возвращает отказ без переноса.
- Блокировка пользователя: unlink выполняется транзакционно после подсчёта способов; последний способ всегда остаётся.
- Гонка двух link/unlink: итоговая уникальность находится в БД; сервис переводит конфликт в безопасный отказ.
- Несогласованная миграция: схема и код совместимы до backfill за счёт legacy fallback. Скрипт только показывает план по умолчанию и требует явный `--apply`; в этом прогоне он не запускается ни против какой БД.
- Восстановление: до развёртывания — обычный revert единственного коммита ветки. После будущего аддитивного применения таблицу можно оставить неиспользуемой при откате кода; перенос не удаляет legacy-поля.

Verdict: GO WITH CONDITIONS — тесты обязаны доказать аутентифицированную привязку, отказ при чужой личности, запрет последнего unlink, LOCAL через email, legacy fallback и dry-run без записи.

## Шаги

1. RED: зафиксировать schema/repository/auth/API/backfill/UI contracts и три правила безопасности.
2. GREEN: добавить модель, слой данных и совместимый поиск при входе.
3. GREEN: добавить аутентифицированные list/link/unlink endpoints и профильную секцию со всеми состояниями.
4. GREEN: добавить dry-run-first backfill и операторскую документацию без запуска.
5. Проверить focused-набор, затем root-owned gates из контракта эпика и независимый security review.

## Не входит

- Применение схемы или backfill к любой базе.
- Push, merge, deploy, SSH, работа с production.
- Перенос личности между пользователями, связывание по email внешнего провайдера и удаление legacy-полей.
