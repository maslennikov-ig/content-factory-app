# Этап .25 — защита старых локальных команд

Старые `pm2`, `pm2-run` и алиасы в трёх приложениях проверяют локальную БД,
затем запускают существующие приложения в терминале. Они больше не удаляют
процессы общего PM2 и не вызывают изменение схемы. Стартер `Dockerfile.dev`
также проходит через защиту до запуска дочерних команд.

Разрешён только известный профиль из `.env.example`: пользователь `cf-dev`,
база `cf-dev-db`, loopback-хост и явный порт `5433`. Рабочие/неоднозначные URL,
конфликты `.env`, production-окружение и попытки передать другую схему или
подключение отклоняются заранее. Пароль и полный URL не выводятся.

Изменение схемы и сброс выполняются только при явном подтверждении:

```bash
pnpm run prisma-db-push --dry-run
pnpm run prisma-db-push --apply --confirm-local cf-dev-db
pnpm run prisma-reset --dry-run
pnpm run prisma-reset --apply --confirm-local cf-dev-db
```

Последняя команда удаляет все данные **локальной** базы. Обычный push больше
не содержит `--accept-data-loss`; reset вызывает установленный Prisma один раз.
Dry-run не запускает дочерних команд и не подключается к БД.

60 новых проверок прошли на временных копиях с подставными командами:
обычный запуск, явный setup/reset, отказ для рабочих адресов, конфликтов и
подмены параметров, отсутствие секретов в сообщениях и передача ошибки дочерней
команды. Живые БД и общий PM2 не использовались — так требует исходный критерий.
Итоговые проверки: [root-acceptance.actual.json](root-acceptance.actual.json).

Рабочий сервис остаётся на принятой версии `2a53727594a1`: API, вход и идентификатор
исходников проверены только чтением. Production-стартер, схема, зависимости и
код приложений не менялись; повторная выкладка для локальных команд не нужна.
Это защита штатных алиасов, а не прямого запуска Prisma или намеренных туннелей.
