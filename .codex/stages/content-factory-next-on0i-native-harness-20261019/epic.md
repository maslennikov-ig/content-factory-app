# Нативный Mastra: эпик интеграции помощника

Эпик Beads: `content-factory-next-on0i`. Сохранены прежний ID и история задачи.
Исполнитель нового чата — **Gemini Argon**; модель самого помощника выбирается
отдельно. В тот же эпик включено обновление совместимой стабильной связки Mastra
(проверенная 19 октября цель — core 1.78.0; сейчас установлен 1.71.0).
Это подготовка к реализации. Код продукта пока не переводился на
новый runtime, публикация и деплой запрещены.

## Результат, который должен получить пользователь

Помощник сам понимает задачу и материал, решает, нужен ли поиск, какие источники
прочитать, какие инструменты вызвать и когда задать вопрос. Он может использовать
уже готовое исследование, писать и редактировать материалы, выполнять долгую
работу и возвращаться к ней после переподключения. Чаты находятся в боковом меню,
«+» создаёт новый; история, черновики и подтверждения сохраняются.

Технический план с файлами, зависимостями и критериями:
[2026-10-19-native-mastra-harness.md](../../../docs/superpowers/plans/2026-10-19-native-mastra-harness.md).

## Какие нативные возможности используем

| Возможность Mastra | Как встроить в продукт и что заменить |
| --- | --- |
| Agent и createTool | Сохранить нативный цикл; сделать инструменты совместимыми друг с другом, вместо обязательной последовательности подготовки |
| AgentController и Session | Управление задачей и отдельными чатами вместо собственного цикла HTTP-контроллера; чат появляется при первом сообщении |
| Native scopes и автор сообщения | Серверная привязка пользователя/области/чата и отказ при несовместимых scope, без расширения прав при продолжении |
| Native threads и Memory | Сохранить ID, историю и пагинацию; использовать нативное создание, выбор, переименование и удаление |
| sendMessage, queueMessage, followUp, steer, abort | Обычные сообщения, очередь, уточнение задачи и остановка через готовые API |
| Durable agents, snapshots, observe, recovery | Отвязать работу от соединения и девятиминутного предела; отдельно проверить перезапуск процесса |
| Background tasks и untilIdle | Выполнять долгие инструменты в фоне и доставлять результат в исходный чат |
| Signals и queueSignal | Передавать новые условия и результаты фоновых задач в правильную сессию с сохранением типа сигнала |
| Goals и judge | Хранить цель и проверять результат по реальным артефактам; не объявлять успех только по словам модели |
| ask_user и submit_plan | Модель решает, нужен ли вопрос или план; убрать обязательный шаблон «один вопрос» |
| Native task tools | План и прогресс задачи в нативном хранилище; не создавать второй список задач runtime |
| Subagents | Делегирование исследования, написания и проверки по решению модели с теми же правами и учётом вызовов |
| Skills | Знания о продукте и инструментах вместо жёсткого сценария на конкретные слова, дату или вид материала |
| toModelOutput | Давать модели компактный результат; сохранять все источники и возможность полного чтения |
| ToolCallFilter и context processors | Убирать повторную передачу больших старых результатов без удаления оригинальной истории |
| Working/Observational Memory | Нативное сжатие и атомарные обновления PostgreSQL без потери полей при конкурентной работе |
| getMessages и viewAttachment | Читать текущий разговор и фактические прежние изображения/PDF, не только их описания |
| Workspace и чтение источников | Авторизованный доступ к полным данным по ссылке/диапазону; без открытого доступа к файловой системе сервера |
| ToolSearchProcessor | Искать и подгружать нужный инструмент из разрешённого каталога вместо искусственного уменьшения возможностей модели |
| ModelSelectionProcessor | Выбор из настроенных моделей по сложности с безопасным отказом от выбора; проверять качество и стоимость всей задачи |
| Native model fallbacks и StreamErrorRetryProcessor | Автоматические повторы с задержкой и переход по настроенному списку моделей; расширить существующее меню, сохранять прогресс и прекращать попытки по Stop |
| Native gateways и error processors | Сохранить настройки провайдера и учёт всех попыток, убрать наложение нескольких механизмов повторных запросов |
| Native approvals, beforeApproval, suspend/resume | Исправлять неверный запрос до карточки; после ответа перепроверять права и содержимое; native resumed-события снимают ожидание |
| Schedules | Только явно запрошенные продолжения задачи помощника; существующие расписания публикаций Temporal сохраняются |
| Signal providers | Использовать нативную доставку и состояние; новые внешние подписки подключать только при реальной необходимости |
| Observability, scorers/evals | Связать нативные события с фактическими вызовами и записями; не выдавать тестовый ответ за качественный результат |
| AI SDK и готовые UI-интеграции | Подключить события, карточки и переподключение к существующему интерфейсу; сохранить стандартное боковое меню |
| MCP и workflows | Общие инструменты и правила с чатом/ручными экранами, нативное восстановление без дублирования бизнес-логики |

Полный каталог включает и смежные возможности. Shell, Code Mode, coding agent,
новые мессенджеры, голос, векторная инфраструктура и deployment-адаптеры не
включаются автоматически: для них нет потребителя в этом запросе. Нативные
возможности используются там, где они выполняют задачу продукта.

## Границы удаления хардкода

Удаляем предписанный смысловой маршрут, повторную обязательную подготовку,
ограничение времени из срока блокировки, лишние очереди, шаблоны завершения и
дублирующее управление сессиями. Отдельно проверяем, где общее запрещение
параллельных инструментов можно заменить нативной конкурентностью.

Сохраняем права доступа, принадлежность чата, реальные квоты, защиту секретов,
согласие на конкретную публикацию/удаление, ревизии и защиту от повторных записей.
Нативное восстановление может повторно вызвать инструмент — это не гарантия
однократной публикации от имени пользователя.

## Реализация и приёмка

В Beads создано семь задач с зависимостями: обновление SDK и нативные сессии; контекст и составные
инструменты; durable/background и восстановление; автономность; модели и учёт;
интерфейс; единый нативный путь и удаление заменённого кода. Статусы ведутся в
Beads, а не в этом документе.

В плане 31 сценарий: разные темы и виды материала, запрос без предыдущего поста,
явное «не ищи», использование готового исследования, неполные источники,
большие результаты, несколько пользователей/чатов, переподключение, фактический
перезапуск, Stop и поздний ответ, подтверждения, выбор модели, цели, делегирование,
уточнение в процессе, отложенная задача и равенство результатов чата/MCP/экранов.
Offline-проверки и настоящие вызовы настроенных моделей/поиска различаются.
Рабочее состояние доказывается UI/API и сохранёнными результатами; одних проб
наличия SDK или зелёных моков недостаточно. Все проверки выполняются локально.
