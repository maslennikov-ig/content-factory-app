## 2. 收集哪些数据

### 2.1 注册与账户

当您创建账户时，以下内容会被保存：

- 您的电子邮件地址。
- 您的密码——不是密码本身，而是它的 bcrypt 哈希值。密码无法从哈希值中还原，我们也不知道它。
- 您的登录方式：密码，或者 Telegram 之类的外部服务以及该服务签发的标识符。
- 注册时看到的 IP 地址和浏览器 User-Agent 字符串。
- 工作区名称，如果您填写了的话。
- 时区。
- 您同意订阅通讯的记录及其时间，如果您勾选了复选框。

之后您可以补充名字、姓氏、一段简短描述和头像。这些都不是必填项。

注册是开放的，但新账户在管理员批准之前无法使用。批准之前，账户虽然存在却什么也做不了：不签发会话，不发送激活邮件，任何 API 请求都会被拒绝。

### 2.2 使用服务

在您使用服务期间，数据库保存您放进去的内容：帖子正文、上传的文件、发布计划、评论、设置。如果您连接了社交网络频道，该网络签发的访问令牌也会被保存——没有它，服务就无法代表您发布。AI 提供商密钥，如果您填写了，会加密保存。

另有一份单独的 AI 使用日志。它只记录哪个操作被允许运行：组织、模式、操作名称、提供商、模型和准入结果。其中没有提示词，没有帖子正文，也没有模型输出。

为了把您的文本与机器所写的文本区分开来，服务会将它与服务中其他作者的文本进行比较。这项工作由服务器端的任务完成：它读取这些文本，据此计算数字，对外只输出数字——一组分数分布和两条边界。没有任何他人的句子会进入您的工作空间：既不会显示在屏幕上，也不会进入给模型的提示，更不会写入日志。您自己的文本同样会参与为其他作者所做的这种比较。

当服务提出草稿而您发送了自己的版本时，会保存这一对：模型提出的内容和您发送的内容。这样做是为了让相似性检查学会把机器文本与您的文本区分开。这一对数据的存续期与它所属的化身相同：删除化身，这些修改也会随之删除。

### 2.3 公开页面与演示

公开页面和产品演示统计各类事件发生了多少次。发送的字段正好有五个：

- 事件名称——四者之一：着陆页浏览、演示开始、演示结束、注册开始。
- 页面语言——`ru` 或 `en`。
- 窗口宽度区间——四个词之一，绝不包含实际尺寸。
- 界面版本。
- 演示步骤。

此外别无他物。没有 IP 地址，没有 User-Agent，没有来源页面，没有 Cookie，没有访客标识符，没有电子邮件地址。所有这些都被累加进每日计数器：每一天和每一组取值一行，其中只有一个数字。这些数据无法把一位访客与另一位区分开。

另有两个事件——完成的注册和工作区激活——由服务器自己记录。它保存一张回执：事件名称和一次单向密码学变换的结果。回执的存在是为了同一个事件不被计算两次。它不带地址，不带姓名，也不带 IP。

为了防止有人用请求淹没计数器，这里有频率限制。它按一个临时键来统计请求，该键由 IP 地址经过带随机密钥的单向变换得出。这个键只存活一分钟，并且只存在于运行中进程的内存里。IP 地址本身从不被写下。

### 2.4 Cookie

本服务设置的 Cookie：

- `auth` —— 您的会话。登录后出现，最长保留一年。没有它，登录无法工作。
- `showorg` —— 打开哪个工作区。当工作区不止一个时出现。
- `org` —— 加入他人工作区的邀请。存活 15 分钟。
- `oauth_state` —— 一项简短校验，确认通过外部服务的登录回到了发起它的那个浏览器。存活 5 分钟。
- `i18next` —— 您选择的界面语言。

没有广告 Cookie。没有第三方分析 Cookie。上述 Cookie 没有一个会跟着您去别的网站。

### 2.5 错误报告

出问题时，服务会把错误报告发给运行在同一台主机上的自有收集器。报告包含事件标识符、时间、级别、环境、构建版本、服务名称、错误类型和堆栈帧——相对于仓库根目录的文件路径、函数名、行号和列号。

其中没有用户，没有请求，没有请求头，没有 Cookie，没有 IP 地址，没有 User-Agent，也没有您正在写的任何文字。事件是按一份允许字段的清单重新组装的，而不是原样转发。

### 2.6 本产品没有的东西

这一点值得直说，因为它并不常见。本产品完全没有第三方产品分析。PostHog、Plausible、Google Tag Manager、dub、datafa.st、Facebook 像素、托管版 Sentry 和 Chatbase 聊天挂件，都已连同其依赖一并移除，把其中任何一个装回来都会导致自动检查失败。线上页面不加载任何外部脚本。字体由我们自己的服务器提供，而不是来自字体 CDN。

没有画像分析。不存在基于您的数据对您作出的自动化决策。您的数据不会被出售。

## 3. 为什么使用这些数据

- 地址和密码——让您能够登录，也让我们能把您的账户与别人的区分开。
- 注册时的 IP 地址和 User-Agent——用于应对注册滥用和密码猜测。
- 工作区内容——让服务做您为之而来的那件事。
- 已连接频道的令牌——把帖子发布到您指定的地方。
- 公开页面的计数器——在不盯着人看的前提下了解产品是否好用。
- 错误报告——修好出问题的地方。
- 用于通讯订阅的地址——只有在您勾选了复选框时。

上述几乎全部内容之所以被处理，是因为交付您创建账户时所要求的东西需要它们。通讯订阅不同：它依据您的同意进行，而您可以随时撤回该同意。

## 4. 还有谁会收到数据

接收方的完整清单以及各自收到什么，见另一份文件《数据接收方》。简要来说：

- 邮件投递服务 Resend 收到服务邮件的收件地址、主题和正文：账户激活、密码重置、地址确认。没有帖子内容，也没有平台令牌。
- 通讯订阅系统 Listmonk 运行在我们自己的主机上，只有在明确同意之后才会收到您的地址。它不会离开这台主机。
- 我们自己主机上的自有错误收集器，收到 2.5 节所描述的内容。
- 如果您通过 Telegram 登录，Telegram 会参与其中。
- OpenAI、OpenRouter 和 Tavily 收到提示词、帖子正文和搜索查询——但仅当某个工作区自行配置了 AI 时。一个组织的密钥绝不会用于另一个组织。
- 社交网络 API 收到帖子内容和文件——在您连接了频道并要求发布时。
- 您指定的某个地址会收到完整的帖子，如果您设置了指向它的 Webhook。

只有在法律要求时，数据才会交给公权力机关。

我们不出售数据，也不把它交给广告主。

## 5. 数据在哪里处理

服务器位于荷兰。数据库、文件、通讯订阅系统和错误收集器都运行在它上面。

部分服务邮件会经由 Resend 发出，这是一家美国公司，从 `eu-west-1` 区域发送本产品的邮件。这意味着您的电子邮件地址和一封服务邮件的正文会离开荷兰。除此之外没有别的东西离开，除非您自己连接了 AI、社交网络频道或 Webhook。

## 6. 数据保存多久

- 账户数据和工作区内容——只要账户还存在。
- 所提草稿与所发文本的配对——只要收集它们的化身仍然存在。删除化身会立即删除它们。
- 注册回执和 AI 使用日志——90 天。此后由一项每日任务删除。
- 来自公开页面的每日计数器——无限期保存。它们不含任何与人有关的内容：一个日期、一个事件名称、一种语言、一个宽度区间、一个界面版本、一个步骤和一个数字。
- 错误报告——按收集器中配置的期限。
- 数据库备份有自己的周期。已删除的数据会随着备份轮换而从中消失。

## 8. 如何删除您的账户和数据

界面中目前还没有“删除账户”按钮。请给 Telegram 机器人 [@content_factory_adtbot](https://t.me/content_factory_adtbot) 发消息，并告知该账户使用的电子邮箱地址。我们可能会要求您提供额外的身份证明。之后，我们会删除该账户及其内容。

无需询问我们、您可以自己完成的事：

- 断开社交网络频道。向它的发布会立即停止，该频道从界面中消失。这条记录会被标记为已删除，但在账户数据被清除之前仍留在数据库中；
- 删除帖子、文件、签名、集合和 Webhook；
- 删除您填写过的任何 AI 提供商密钥；
- 用邮件本身中的链接退订通讯。

## 9. 年龄

本服务面向成年人。我们不会在知情的情况下收集儿童的数据。如果发现某个账户由儿童创建，我们会删除它——请写信告诉我们。

## 10. 数据如何得到保护

- 密码仅以 bcrypt 哈希值的形式保存。
- 登录密码必须至少 12 个字符。
- AI 提供商密钥和组织 API 密钥加密保存。
- 连接通过 HTTPS 进行，会话 Cookie 标记为 `secure` 和 `httpOnly`，其作用范围被限定在服务的确切地址上。
- 注册、登录、密码重置和重新发送激活邮件都设有频率限制。
- 注册需要管理员批准，因此陌生人的账户不会自行出现在服务器上。

完美的安全并不存在，我们也不作此承诺。我们承诺的是修好我们了解到的问题。
